# С чего начинать новый проект

Порядок первого дня. Каждый пункт ссылается на правило в
[`rules/`](rules/) — там инцидент, из которого он вырос.

> **Не делайте всё сразу.** Список отсортирован по цене ошибки: верхнее дороже
> всего обходится, если пропустить. Нижнее можно отложить до первого релиза.

## В первый день

- [ ] **Гейт перед коммитом — одной командой.** Не чек-лист в документации, а
      исполняемый скрипт: тесты, линтер, форматирование, типы, секреты.
      → [`002`](rules/002-rule-without-mechanism.md)
- [ ] **CI на всех целевых ОС**, а не только на удобной. Слепая зона окажется
      ровно там, где продуктом пользуются руками.
- [ ] **Защита основной ветки** с обязательными проверками и **пустым списком
      обходов** — правило действует и на владельца.
      → [`002`](rules/002-rule-without-mechanism.md)
- [ ] **Гейт на секреты.** Белый список полей, а не чёрный: чёрный не переживёт
      появления нового поля, а именно так секрет и утекает.

## До первого PR от агентского окна

- [ ] **Транспорт к API — самый дешёвый из доступных.** Проверьте цену операции
      до того, как построите на ней конвейер.
      → [`001`](rules/001-transport-rest-not-graphql.md)
- [ ] **Правила именования веток**, если автоматика на них реагирует. Молчаливая
      зависимость от имени — источник поломок, которые не гуглятся.
      → [`003`](rules/003-branch-name-is-a-switch.md)
- [ ] **Обязательные метки и связь PR с задачей.** Без связи задача не закроется
      при мерже, а приоритет очереди наследовать неоткуда.

## До первого релиза

- [ ] **Changelog фрагментами**, а не правкой общего файла: иначе конфликт на
      каждом втором PR, а запись после релиза пишется по памяти и врёт.
- [ ] **Ни одной цифры в документации руками.** Либо пересчитывается скриптом,
      либо её нет.
      → [`005`](rules/005-hand-written-numbers-rot.md)
- [ ] **Приёмка опубликованного пакета** в чистом окружении — проверка того, что
      уехало, а не того, что лежит в рабочем дереве.

## Когда окон становится больше одного

- [ ] **Срок жизни окна** — три-пять дней, дальше перезапуск с эстафетой
      ссылками.
      → [`006`](rules/006-window-lifetime.md)
- [ ] **Различайте три состояния окна:** работает · ждёт разрешения · брошено.
      Ответы на них разные, а внешняя картина одинаковая.
      → [`007`](rules/007-blocked-window-looks-alive.md)
- [ ] **Автоматика пропускает и метит, а не падает** на предсказуемом
      препятствии.
      → [`004`](rules/004-conflict-is-normal-not-outage.md)

## Чего НЕ делать в первый день

- **Не переносить чужой свод правил целиком.** Правило без своей истории не
  соблюдается — оно занимает место и создаёт видимость дисциплины.
- **Не писать правила про механизмы, которых нет.** Правило без гейта —
  обещание.
- **Не строить сервер, пока хватает файла.** Хранилище на git переживает
  эфемерные окружения и не добавляет точки отказа.

## Проверка себя через месяц

- Сколько правил из ваших нарушено за месяц? Каждое нарушенное — кандидат либо
  в гейт, либо на удаление.
- Какие цифры в документации устарели? Все, что не пересчитываются.
- Сколько времени ушло на ожидание конвейера, которое можно было заметить
  раньше?
