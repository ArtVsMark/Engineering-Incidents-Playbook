# С чего начинать новый проект

Порядок первого дня и дальше. Каждый пункт ссылается на правило в
[`rules/`](rules/README.md) — там инцидент, из которого он вырос.

> **Не делайте всё сразу.** Список отсортирован по цене ошибки: верхнее дороже
> всего обходится, если пропустить. Разделы ниже включаются по мере того, как
> проект дорастает до их предмета, а не по расписанию.

**Сначала подключитесь, а потом читайте список.** Половина того, что стоит
ниже, у каталога уже собрана инструментом: [`CONNECT.md`](CONNECT.md) — одна
команда кладёт ответ по каждому правилу, канал обратно и ежедневные
«входящие» с очередью и с тем, что у соседей уже решено. Переносить руками
собранное инструментом значит завести вторую реализацию
([090](rules/ru/090-shared-helpers-move-up-not-sideways.md)).

Исполняемые заготовки — в [`templates/`](templates/README.md) — для того, у
кого прогонов GitHub нет. Их берут и правят, а не копируют целиком: правило
без своей истории не соблюдается.

## В первый день

- [ ] **Гейт перед пушем — одной командой.** Не чек-лист в документации, а
      исполняемый скрипт: тесты, линтер, форматирование, типы, секреты.
      Заготовка — [`templates/preflight.py`](templates/preflight.py).
      → [`002`](rules/ru/002-rule-without-mechanism.md)
- [ ] **У каждой проверки три исхода**, а не два: чисто · есть находки ·
      **проверка не отработала**. Третий различают по наличию результата, а не
      по коду возврата.
      → [`039`](rules/ru/039-three-outcomes-not-two.md)
- [ ] **Гейт, не нашедший предмета проверки, падает.** Ноль файлов, ноль
      совпадений, отсутствующий раздел — это ошибка входа, а не «чисто».
      → [`075`](rules/ru/075-a-guard-that-finds-nothing-must-fail.md)
- [ ] **Секреты — по списку разрешённого**, а не запрещённого: чёрный список не
      переживёт появления нового поля, а именно так секрет и утекает.
      → [`068`](rules/ru/068-allowlist-not-denylist.md)
- [ ] **CI на всех целевых ОС**, а не только на удобной, и с ручным запуском:
      события теряются. Заготовка — [`templates/ci.yml`](templates/ci.yml).
      → [`104`](rules/ru/104-event-driven-automation-needs-a-manual-button.md),
      [`018`](rules/ru/018-cloud-checks-nodes-local-checks-chain.md)
- [ ] **Защита основной ветки** с обязательными проверками и **пустым списком
      обходов** — правило действует и на владельца, иначе это обещание.
      → [`002`](rules/ru/002-rule-without-mechanism.md)
- [ ] **Версия — из одного источника.** Руками не правится нигде, плюс проверка
      согласованности перед выпуском.
      → [`035`](rules/ru/035-version-is-never-edited-by-hand.md)
- [ ] **Карта направлений, а не список ролей.** Обойдите артефакты и у каждого
      спросите владельца: каталог, формат, поверхность, канал. Артефакт без
      владельца сам называет недостающее направление. **Непокрытое пишется как
      непокрытое** — незаданный вопрос не оставляет следа, и дыру в составе
      нельзя увидеть, читая список ролей.
      → [`082`](rules/ru/082-roles-must-cover-every-layer.md),
      [`062`](rules/ru/062-a-role-must-be-able-to-object.md)
- [ ] **Обязательное поле проверяется на полноту, а не на непустоту.** «Не
      дошли руки» — это статус, а не отсутствующая запись.
      → [`128`](rules/ru/128-a-required-field-is-checked-for-completeness.md)
- [ ] **Генератор читает источники, а не свой вывод.** Иначе данные живут до
      первой смены формата и обнуляются молча.
      → [`125`](rules/ru/125-a-generated-file-is-not-a-store.md)

## До первого PR от агентского окна

- [ ] **Транспорт к внешнему API — самый дешёвый из доступных.** Проверьте цену
      операции **до** того, как построите на ней конвейер: разница бывает
      трёхсоткратной.
      → [`001`](rules/ru/001-transport-rest-not-graphql.md),
      [`017`](rules/ru/017-measure-quota-do-not-guess.md)
- [ ] **Правила именования веток**, если автоматика на них реагирует. Молчаливая
      зависимость от имени — источник поломок, которые не гуглятся.
      → [`003`](rules/ru/003-branch-name-is-a-switch.md)
- [ ] **Метки обязательны и разделены на два класса:** содержание ставит автор,
      конвейер — автоматика. Заготовка —
      [`templates/labels.yml`](templates/labels.yml).
      → [`064`](rules/ru/064-labels-are-machine-input-not-decoration.md)
- [ ] **Связь изменения с задачей** обязательна: без неё задача не закроется при
      мерже, а приоритет очереди наследовать неоткуда.
      → [`064`](rules/ru/064-labels-are-machine-input-not-decoration.md)
- [ ] **Имя окна начинается с окружения**, а не с задачи: `[WEB]` · `[LOCAL]` ·
      `[CLI]`.
      → [`038`](rules/ru/038-window-name-declares-its-environment.md)
- [ ] **Стартовое сообщение окна — четыре раздела**, контекст передаётся
      ссылками. Заготовка —
      [`templates/session-opening.md`](templates/session-opening.md).
      → [`006`](rules/ru/006-window-lifetime.md)
- [ ] **Атрибуция сверяется со списком согласованных имён и до слияния.**
      Итоговый коммит собирает площадка, а историю общей ветки не переписать:
      после слияния чинить нечем.
      → [`123`](rules/ru/123-attribution-is-verified-on-the-final-history.md)
- [ ] **Запись в журнал — отдельным файлом**, а не строкой в общий: иначе
      конфликт на каждом втором PR, а на конфликтном PR **проверки не
      создаются вовсе**.
      → [`030`](rules/ru/030-changelog-from-fragments.md)
- [ ] **У заморозки есть выход, не проходящий через замороженное действие.**
      Иначе первое же мигание превращает защиту в ловушку, а выглядит она
      здоровой.
      → [`126`](rules/ru/126-a-freeze-needs-a-thaw-path.md)

## До первого релиза

- [ ] **Changelog фрагментами**, а не правкой общего файла: иначе конфликт на
      каждом втором изменении, а запись после релиза пишется по памяти и
      описывает код вместо изменения для пользователя.
      → [`030`](rules/ru/030-changelog-from-fragments.md)
- [ ] **Ни одной цифры в документации руками.** Либо её переписывает сборка,
      либо её нет. Число в прозе допустимо при трёх условиях сразу: маркер,
      сборка из порождающего источника и **падение сборки при пропаже
      маркера**. Значок несёт подпись, а не значение, — парсер и скринридер
      числа из него не получают.
      → [`005`](rules/ru/005-hand-written-numbers-rot.md),
      [`127`](rules/ru/127-a-number-in-prose-needs-a-guarded-marker.md)
- [ ] **Инварианты релизного конвейера проверяются заранее.** Необратимый шаг
      нельзя проверить прогоном: порядок шагов, отказ на пустом `dist/`,
      объявленные права.
      → [`074`](rules/ru/074-one-shot-irreversible-steps-get-their-own-guard.md)
- [ ] **Приёмка опубликованного пакета** в чистом окружении — проверка того, что
      уехало, а не того, что лежит в рабочем дереве.
- [ ] **Умолчание — в пользу пользователя.** Всё, что собирает его данные,
      выключено; включается одним движением.
      → [`095`](rules/ru/095-the-default-is-chosen-for-the-user.md)
- [ ] **Что продукт создал — он умеет удалить.** «Удалите файл вручную» — не
      способ.
      → [`112`](rules/ru/112-whatever-the-tool-created-it-must-be-able-to-delete.md)
- [ ] **Сообщения ведут туда, что есть у получателя.** Автор видит репозиторий,
      пользователь — установленный пакет.
      → [`076`](rules/ru/076-messages-point-at-what-the-user-actually-has.md)

## Когда окон становится больше одного

- [ ] **Срок жизни окна** — три-пять дней, дальше перезапуск с эстафетой
      ссылками.
      → [`006`](rules/ru/006-window-lifetime.md)
- [ ] **Сменили правила работы — перезапустите окна.** Контекст читается один
      раз, при старте; правка документа на текущие окна не действует.
      → [`047`](rules/ru/047-rule-change-restarts-the-windows.md)
- [ ] **Различайте три состояния окна:** работает · ждёт разрешения · брошено.
      Ответы разные, а внешняя картина одинаковая.
      → [`007`](rules/ru/007-blocked-window-looks-alive.md)
- [ ] **Вмешательство автоматики — по всем условиям сразу.** Ложное
      срабатывание затопчет чужую работу молча.
      → [`063`](rules/ru/063-automatic-intervention-needs-all-conditions.md)
- [ ] **Автоматика пропускает и метит, а не падает** на предсказуемом
      препятствии.
      → [`004`](rules/ru/004-conflict-is-normal-not-outage.md)
- [ ] **Состояние вычисляется из живых артефактов**, а не ведётся файлом-реестром.
      → [`049`](rules/ru/049-derive-state-from-live-artifacts.md)
- [ ] **В очереди обновляется только голова**, а порядок задаётся правилом, а не
      готовностью.
      → [`052`](rules/ru/052-only-the-head-of-the-queue-moves.md),
      [`053`](rules/ru/053-queue-order-is-a-rule-not-arrival.md)

## Когда работа идёт параллельными исполнителями

- [ ] **Волнами фиксированного размера**, а не залпом; между волнами — разбор.
      → [`031`](rules/ru/031-waves-not-salvos.md)
- [ ] **Зона одного исполнителя маленькая:** роль дробится на двух-трёх, в плане
      не больше трёх пунктов.
      → [`034`](rules/ru/034-small-zone-per-executor.md)
- [ ] **В задании — числа и запреты окружения.** Исполнитель не видит того, что
      знает хост. Заготовка —
      [`templates/executor-brief.md`](templates/executor-brief.md).
      → [`117`](rules/ru/117-numeric-limits-belong-in-the-task-spec.md),
      [`061`](rules/ru/061-environment-bans-belong-in-the-task.md)
- [ ] **Разбор после каждой волны, и качество важнее механики:** пять
      «успешных» исполнителей способны выдать связный мусор.
      → [`060`](rules/ru/060-debrief-every-wave-quality-first.md)
- [ ] **Темп считается от лимита**, а не от желания: упор в стену теряет всю
      волну.
      → [`033`](rules/ru/033-pace-from-limit-not-desire.md)
- [ ] **Исполнители возвращают данные — файлы правит хост.**
      → [`015`](rules/ru/015-agents-return-data-host-writes-files.md)
- [ ] **Сборщик результатов проверяется наравне с работой:** сверка «сколько
      вошло / сколько вышло» обязательна.
      → [`116`](rules/ru/116-the-collector-script-is-a-source-of-loss.md)

## Когда доходит до аудита

- [ ] **Планировать от поверхностей продукта**, а не от файлов: обход по файлам
      не встретит того, чего в коде нет.
      → [`019`](rules/ru/019-audit-from-surfaces-not-files.md)
- [ ] **Роль запускает продукт**, если её предмет там наблюдаем: плотность
      находок отличается кратно.
      → [`032`](rules/ru/032-role-must-run-the-product.md)
- [ ] **Тяжесть ставит не тот, кто нашёл** — и опровергателю нужна
      калиброванная шкала, иначе он понижает всё подряд.
      → [`086`](rules/ru/086-the-finder-does-not-grade-the-finding.md)
- [ ] **Находка не с той поверхности — гипотеза**, а не находка с тяжестью.
      → [`037`](rules/ru/037-finding-status-depends-on-window.md)
- [ ] **Отклонённая находка фиксируется с причиной**, иначе вернётся следующей
      ревизией.
      → [`026`](rules/ru/026-rejected-findings-must-be-recorded.md)
- [ ] **Критик проверяет метод фазы**, а не предмет. Заготовка документа —
      [`templates/audit-document.md`](templates/audit-document.md).
      → [`088`](rules/ru/088-the-critic-checks-the-method-not-the-subject.md)
- [ ] **Закрытие контейнера — не доказательство закрытия работы:** перед
      архивацией счётчик единиц без исхода должен быть ноль.
      → [`121`](rules/ru/121-closing-the-container-is-not-closing-the-work.md)

## Когда документации становится много

- [ ] **Делить по читателю**, а не по теме.
      → [`021`](rules/ru/021-split-docs-by-reader.md)
- [ ] **Одна тема — один канонический документ**, остальные ссылаются; в главном
      файле компактный триггер. Заготовка —
      [`templates/CLAUDE.md`](templates/CLAUDE.md).
      → [`022`](rules/ru/022-one-canonical-document.md),
      [`029`](rules/ru/029-triggers-and-canon.md)
- [ ] **Решение записывается с отвергнутыми вариантами** и не правится задним
      числом. Заготовка —
      [`templates/adr-template.md`](templates/adr-template.md).
      → [`042`](rules/ru/042-decision-records-its-alternatives.md),
      [`043`](rules/ru/043-decisions-are-superseded-not-edited.md)
- [ ] **У живого документа фиксированное окно**, остальное переезжает в архив
      дословно.
      → [`108`](rules/ru/108-a-living-document-keeps-a-fixed-window.md)

## Когда проект не первый

- [ ] **Свой каталог правил**, и правило записывается в него тем же заходом, что
      и правка свода проекта. Заготовка записи —
      [`templates/rule-template.md`](templates/rule-template.md).
      → [`080`](rules/ru/080-every-new-rule-goes-into-the-catalogue.md)
- [ ] **Указатель каталога генерируется** из самих записей, а не ведётся руками.
      → [`120`](rules/ru/120-how-to-run-a-rule-catalogue.md)
- [ ] **«Чем держится» живёт у потребителя, а не в каталоге.** Одно правило в
      разных проектах держится по-разному: гейтом · шагом процесса · ничем.
      Каждый проект отвечает за **каждое** правило файлом: действует и чем ·
      отклонено и почему · нет предмета · ещё не смотрели. Признак «есть след»
      склеивает три разных состояния, и самое дорогое из них — **«не знали»**.
      → [`129`](rules/ru/129-a-catalogue-needs-a-consumption-contract.md)
- [ ] **Правило доезжает вместе с кандидатами из бэклога получателя.**
      «Полезная мысль» — отказ с отсрочкой; три свои открытые задачи — работа
      на завтра.
      → [`130`](rules/ru/130-a-rule-arrives-with-candidates-from-the-backlog.md)
- [ ] **Сколько правил не обеспечено ничем — метрика**, и она должна
      уменьшаться. Растворённая в тексте, она выглядит отсутствующей.
      → [`120`](rules/ru/120-how-to-run-a-rule-catalogue.md)
- [ ] **Правило, которое нельзя проверить машиной, называется явно** — с
      пометкой, что гейта нет и почему.
      → [`057`](rules/ru/057-unmechanizable-rules-are-named-explicitly.md)

## Чего НЕ делать в первый день

- **Не переносить чужой свод правил целиком.** Правило без своей истории не
  соблюдается — оно занимает место и создаёт видимость дисциплины. Это
  относится и к этому каталогу.
- **Не писать правила про механизмы, которых нет.** Правило без гейта —
  обещание; либо гейт, либо честная пометка «механизма нет».
  → [`002`](rules/ru/002-rule-without-mechanism.md),
  [`057`](rules/ru/057-unmechanizable-rules-are-named-explicitly.md)
- **Не заводить роль, которая только соглашается.** Нет своего возражения — это
  раздел документации, а не роль.
  → [`062`](rules/ru/062-a-role-must-be-able-to-object.md)
- **Не обобщать по двум случаям.** Шов вводят рано, абстракцию — с третьего.
  → [`093`](rules/ru/093-seam-early-generalisation-late.md)
- **Не строить сервер, пока хватает файла.** Хранилище на git переживает
  эфемерные окружения и не добавляет точки отказа.
- **Не показывать широко до настоящего прогона.** Огласка умножает и хорошее, и
  плохое.
  → [`106`](rules/ru/106-publicity-multiplies-both-sides.md)

## Проверка себя через месяц

- Сколько правил из ваших нарушено за месяц? Каждое нарушенное — кандидат либо
  в гейт, либо на удаление.
- **Сколько правил не обеспечено ничем?** Это метрика, и она должна
  уменьшаться. → [`120`](rules/ru/120-how-to-run-a-rule-catalogue.md)
- Какие цифры в документации устарели? Все, что не пересчитываются.
- Есть ли поверхность, которую ни разу не проверяли **запуском**? Она и есть
  слепая зона. → [`019`](rules/ru/019-audit-from-surfaces-not-files.md)
- Сколько времени ушло на ожидание конвейера, которое можно было заметить
  раньше?
- Краснел ли хоть раз каждый из ваших гейтов? Ни разу не краснел — вероятно, он
  ничего не проверяет. → [`075`](rules/ru/075-a-guard-that-finds-nothing-must-fail.md)
