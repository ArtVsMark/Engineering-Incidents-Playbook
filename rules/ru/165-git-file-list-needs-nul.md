# Список путей из git читают по NUL, а проверка называет охват

**Область.** код, гейты

**Ступень.** 3 — гейты и процессы

**Правило.** Перечисляя пути из git для последующего **чтения**, передавай `-z`
и разбирай вывод по NUL. Без него git экранирует имена с не-ASCII символами и
пробелами, построенный путь не разрешается, и файл молча выпадает из обработки.
Проверка, читающая такой список, обязана печатать **охват** — сколько путей
просмотрено и сколько пропущено: без числа её слепота неотличима от чистого
результата.

**Переносится вне Claude Code.** да — предмет принадлежит любому коду, который
берёт список файлов у git и потом их открывает: линтеру, сборщику, поиску
секретов.

## Инцидент

Прогон перед толчком у потребителя запускает четыре гейта и проверяет файлы
будущего коммита на секреты. Список брался как
`git ls-files --cached --others --exclude-standard` с разбором по строкам.

Проверка на подделанных данных: в корень положен файл с заведомым токеном
площадки. Прогон вернул код `0` и напечатал «всё чисто: проверок 5». Токен не
найден. Из двадцати девяти файлов проверялось двадцать восемь — невидимым был
ровно один, с кириллическим именем `утечка.py`.

Первая проба гейта была сделана файлом с латинским именем. Он находился, и
проверка выглядела рабочей — то есть подделка подтвердила ровно тот случай,
который не ломается.

## Почему

Механизм складывается из трёх шагов, каждый из которых по отдельности
безобиден. `core.quotePath=true` — умолчание git, и не-ASCII имя отдаётся
экранированным: `"\321\203\321\202..."`. Код строит `Path` из экранированной
строки, такого файла на диске нет, чтение падает `OSError`. Наконец, обработчик
`except (OSError, UnicodeDecodeError): continue`, написанный ради двоичных
файлов, глотает это молча.

Асимметрия цены здесь предельная. Пропущенный файл в проверке на секреты стоит
утечки; лишний разбор — ничего. И слепая зона пришлась не на экзотику: проект
ведётся по-русски, то есть невидимым оказался **самый вероятный** случай, а не
редкий.

Вторая половина правила — про охват — стоит рядом не для симметрии. Молчание
проверки означает и «ничего не нашла», и «ничего не смотрела», и различить их
читателю нечем ([075](075-a-guard-that-finds-nothing-must-fail.md)). Число
просмотренного делает эти два состояния разными.

## Практические границы

- `-z` у `ls-files`, `diff --name-only`, `status --porcelain` — и разбор по
  `\0`, а не по `\n`;
- `except`, написанный ради ожидаемого случая, не расширяют до соседнего:
  `OSError` рядом с `UnicodeDecodeError` превращает поломку пути в пропуск
  файла;
- охват печатается числом просмотренного, а не словом «чисто»;
- подделка для такого гейта берётся из самого вероятного случая проекта: имя на
  языке, на котором проект ведётся ([037](037-finding-status-depends-on-window.md)).

## Применимость

**Работает** везде, где список путей приходит из git и по нему потом **открывают
файлы**.

**Не работает** там, где список только печатается человеку: экранирование в
выводе читаемо и безвредно, а требование `-z` добавит шум. Не работает и там,
где файлы обходятся по дереву без участия git — экранировать нечего, и от
правила остаётся одна вторая половина, про охват.

**Признак нарушения:** проверка печатает «чисто», не называя, сколько файлов
просмотрела.
