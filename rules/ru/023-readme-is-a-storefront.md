# README — витрина, а не свалка технической памяти

**Правило.** В README только то, что нужно человеку в первые пять минут.
Остальное — по ссылке.

## Инцидент

README рос естественным путём: каждая новая возможность добавляла абзац, каждый
разобранный вопрос — раздел «а если…».

К моменту, когда это заметили, страница отвечала на десятки вопросов сразу — и
поэтому ни на один быстро. Человек, пришедший поставить инструмент, пролистывал
описания внутренних контрактов.

## Что оставить

- описание проекта и бейджи;
- быстрый старт и установка;
- основные режимы работы;
- **ссылки** на подробную документацию.

Всё остальное — в документацию, разложенную по читателю.

## Почему

У README две несовместимые роли: **привлечь** того, кто ещё не решил, и
**обслужить** того, кто уже работает. Первому нужна краткость, второму —
полнота.

Совместить нельзя, и выбирать надо в пользу первого: обслуживать удобнее
специализированным документом, а привлекать больше нечем — второй страницы у
проекта нет.

Отдельно: **числа не вписываются в прозу**. Количество тестов, покрытие, размер
данных живут в бейджах, которые пересчитываются, а не в тексте, который
устаревает молча.

## Применимость

**Работает** для любого публичного проекта.

**Не работает** для крошечных: если вся документация — три абзаца, они и есть
README.

**Регресс неизбежен:** README разрастается снова. Проверять при ревью каждого
PR, добавляющего документацию, — это дешевле, чем чистить раз в полгода.
