# У настроек один якорь и ограниченная зона поиска

**Область.** конфигурация

**Ступень.** 5 — всё остальное

**Правило.** Поиск файла настроек вверх по дереву останавливается на границе
проекта, а не на корне файловой системы. И якорь у всех поверхностей продукта
**один** — иначе один запуск читает настройки из двух разных мест.

## Инцидент

Поиск настроек шёл вверх до самого корня файловой системы и брал первый
попавшийся подходящий файл. Последствия оказались двух видов, и оба неочевидные.

**Чужие параметры.** Верное решение, дающее правильный результат в своей папке,
получало отказ по времени, если этажом выше лежал чей-то файл с другими
параметрами прогона. Причина находилась вне рабочего каталога, и искать её там
никто не догадывался.

**Чужая опечатка.** Синтаксическая ошибка в таком постороннем файле роняла
**любую** команду продукта — включая вывод справки. То есть чужой файл, к
которому пользователь не имеет отношения, делал инструмент неработоспособным
целиком.

Третий дефект был про **якорь**: настройки проекта резолвились от рабочего
каталога, а настройки веб-оболочки — от переданного пути. Один запуск читал два
разных места и вёл себя несогласованно.

Починка: зона поиска ограничена корнем проекта (ближайший вверх каталог с
маркером), якорь общий для всех поверхностей, а битый или недоступный файл даёт
**предупреждение с путём и причиной**, не прерывая работу.

## Почему

Поиск вверх — эвристика, а у эвристики должна быть граница. Без границы область
поиска включает чужие проекты, домашний каталог и системные пути; вероятность
подобрать не тот файл растёт с глубиной, а диагностируемость падает: причина
лежит там, куда никто не смотрит.

Второе: **чужой файл не должен ломать наш запуск**. Всё, что найдено эвристикой,
по определению не гарантировано — значит и обрабатывается как ненадёжный вход:
предупреждение и продолжение, а не исключение. Иначе продукт наследует качество
файлов, которые ему не принадлежат.

Третье, про якорь: настройки образуют **одно** состояние. Две поверхности с
разными точками отсчёта дают два состояния под одним именем, и расхождение
проявляется как «в интерфейсе одно, в терминале другое» — самый трудный для
диагностики класс жалоб.

## Практические границы

- граница поиска — маркер проекта, а не число уровней вверх;
- найденный файл называется в выводе: пользователь должен видеть, **что именно**
  прочитано;
- битый или недоступный файл — предупреждение с путём и причиной, работа
  продолжается на умолчаниях;
- якорь один и задаётся явно при запуске; от него резолвится **всё**, а не
  часть;
- запасной путь (например, относительно расположения самого пакета) применяется
  последним и только если остальные ничего не дали.

## Применимость

**Работает** для файлов настроек, локальных переопределений, кэшей и рабочих
каталогов, которые ищутся вверх по дереву.

**Не работает** для настроек, задаваемых только явным путём, — там поиска нет.

**Признак проблемы:** поведение меняется в зависимости от того, из какой папки
запустили, и объяснить это никто не может.
