# Сторож смотрит на сырое значение: форматирование идёт после него

**Область.** гейты, метрики

**Правило.** Проверка «источник ответил» ставится на **сырое** значение.
Отформатированное значение сторожу не показывают: форматирование теряет ровно
тот признак, по которому сторож узнаёт пустоту, и превращает отказ источника в
правдоподобное число.

## Инцидент

Витрина профиля пересобирает свои числа из живых источников и намеренно падает,
если источник промолчал: «метрика не собралась — ничего не переписываю». Это её
главный механизм, ради него всё и заводилось.

Значение плитки собиралось так:

```python
plate = [(f"{tests // 1000}000+", "tests"), (coverage, "coverage (all OS)"), ...]
...
empty = [key for key, value in {...}.items()
         if not str(value).strip() or (str(value) == "0" and key != "gfi")]
```

Форматирование стоит **до** сторожа. Прогон:

```
источник ответил 4321 -> плитка «4000+ tests» -> сторож ПРОПУСКАЕТ
источник ответил    0 -> плитка «0000+ tests» -> сторож ПРОПУСКАЕТ
источник ответил  999 -> плитка «0000+ tests» -> сторож ПРОПУСКАЕТ
```

Ноль — единственное, что сторож ищет, — до него не доезжает: он уже не `"0"`, а
`"0000+"`. Соседние метрики, которые сторож видит сырыми, при нуле останавливают
сборку штатно. Защита работает у всех, кроме той метрики, которую перед ней
отформатировали.

Цена: на витрине появилось бы «0000+ tests», прогон отчитался бы успехом, и
число прожило бы до тех пор, пока его не заметят глазами, — ровно тот исход, от
которого вся сборка и защищает.

## Почему

**Сторож — предикат над значением, а форматирование меняет тип значения.**
`0` → `"0000+"`, `0.0` → `"0.0%"`, `None` → `"—"`, пустой список → `"нет"`. После
любого из них признак пустоты выражается уже не тем, что проверяют.

**Ошибка не видна при чтении, потому что обе строки правильные по отдельности:**
формат корректный, сторож корректный. Неверен только порядок — а порядок в коде
выглядит как порядок объявления переменных, то есть как ничто.

**Отдельная ловушка в том, на что рассчитан сторож.** Написанный по строке, он
обычно ищет `""` и `"0"` — то есть форму, которую даёт **отсутствие**
форматирования. Он молча предполагает, что до него никто не поработал, и это
предположение нигде не записано.

## Практические границы

- сырое значение доходит до сторожа, а форматирование применяется к тому, что
  уже проверено;
- если в одном списке проверяемых часть ключей сырые, а часть — строки для
  показа, это и есть признак поломки, а не разнообразие;
- «источник промолчал» — третий исход, а не успех
  ([039](039-three-outcomes-not-two.md));
- разбирать свою же строку обратно, чтобы проверить, — не решение, а
  подтверждение того, что сырое надо было донести
  ([122](122-ship-the-raw-value-next-to-the-formatted-one.md)).

## Применимость

**Работает** для любой публикации измеренного: витрины, отчёты, значки, панели,
экспорт метрик — везде, где есть шаг «источник промолчал → не публиковать».

**Не работает** для проверок формы — длины, шаблона, допустимых символов: их
предмет как раз отформатированное, и сырое им не подходит.

**Признак нарушения:** в списке проверяемых значений одни ключи сырые, а другие
уже строки для показа.
