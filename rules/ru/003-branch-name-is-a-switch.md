# Имя ветки может быть переключателем поведения, а не соглашением о стиле

**Область.** конвейер

**Правило.** Если конвейер реагирует на префикс ветки, это надо писать в
правилах первой строкой — и объяснять, что случится при другом имени.

**Переносится вне Claude Code.** частично — переносится сам приём «имя как переключатель», но инцидент и лекарство привязаны к тому, что конвейер читает префикс ветки. Там, где такого чтения нет, правилу нечего охранять.

## Инцидент

Из восьми открытых PR авто-мерж стоял у трёх. Пять зелёных PR стояли часами,
два — по **пятнадцать часов**, при том что все проверки пройдены и конфликтов
нет.

Причина оказалась в имени ветки: workflow, открывающий PR и включающий
авто-мерж, брал только ветки с префиксом `agent/`. Ветки `claude/**`, `fix/**`
проходили тот же путь и останавливались на последнем шаге, ожидая человека.

Со стороны это выглядело как поломка конвейера. Конвейер работал.

## Почему

Цепочка причин длинная, и каждое звено невидимо по отдельности:

1. авто-мерж включается GraphQL-мутацией `enablePullRequestAutoMerge`;
2. REST-эквивалента у неё нет;
3. прокси агентской сессии режет GraphQL целиком;
4. значит окно **физически не может** включить авто-мерж своему PR;
5. умеет только workflow — а он смотрит на префикс.

Ни один участник цепочки не виноват; результат — молчаливое зависание.

## Применимость

**Работает** там, где автоматика фильтрует по имени ветки — а это почти любой
конвейер с автооткрытием PR.

**Не работает** как универсальное соглашение: конкретный префикс — деталь вашей
настройки, и переносить `agent/**` в проект без такого workflow бессмысленно.

**Общий вывод переносим:** любое место, где имя объекта меняет поведение
системы, должно быть названо явно. Молчаливая зависимость от имени — источник
поломок, которые не гуглятся.
