# Комплексная задача ведёт чек-лист, а не перечисление

**Правило.** От трёх пунктов — галочки, а не проза. Иначе состояние задачи
приходится вычислять чтением.

## Инцидент

Задачи с десятком находок описывались списком в теле: «нашли то, сё, пятое,
десятое». По мере работы часть исправлялась, часть отклонялась — тело правили
прозой.

Понять, что осталось, можно было только прочитав всё и сверив с историей
изменений. Счётчик прогресса в трекере при этом показывал ноль: для него задача
была одна и открыта.

## Решение

Чек-лист. Галочка ставится **тем же заходом, что и закрывающее изменение**, и
называет исход: номер изменения либо причину отклонения.

- [x] Находка A — исправлено в #123
- [x] ~~Находка B~~ — отклонена: ложное срабатывание на генерируемом коде
- [ ] Находка C

Отклонённая **зачёркивается, но остаётся** — иначе счётчик врёт (см. правило об
отклонённых находках).

От трёх десятков пунктов — группировка по файлам или зонам. Плоский список из
сотни галочек нечитаем так же, как проза.

## Почему

Чек-лист делает состояние **машинно и визуально считываемым**: трекер сам
показывает «7 из 12», не читая содержимого.

Второе: галочка ставится в момент закрытия, а не «потом при разборе». Проза
требует переписывания — и потому не переписывается.

Условие: **состояние живёт только в задаче**. Дублирование прогресса в документ
даёт два источника, один из которых устареет.

## Применимость

**Работает** для задач с несколькими независимыми пунктами: находки аудита,
списки миграции, чек-листы приёмки.

**Не работает** для задач с одним предметом — там чек-лист лишний.

**У эпика с дочерними задачами** галочки не нужны: прогресс считает сам трекер.
