# Пустой список проверок означает «не стартовало», а не «всё хорошо»

**Область.** CI

**Правило.** Условие «нет красных и нет ожидающих» истинно на пустом множестве.
Проверяйте, что проверки вообще созданы.

## Инцидент

Сразу после пуша гейт готовности сообщал, что PR можно мержить: красных нет,
ожидающих нет.

Проверок не было вовсе — GitHub ещё не успел их создать. Условие «всё зелено»
выполнялось на пустоте.

Родственный случай оттуда же: при конфликте с основной веткой прогон на PR идёт
по merge-коммиту, а он невозможен — **check-runs не создаются вообще**. Со
стороны выглядит как «CI сломался», хотя CI не запускался.

## Почему

Классическая ошибка кванторов: «все элементы удовлетворяют условию» истинно для
пустого множества. Проверка на отсутствие плохого не заменяет проверку на
наличие хорошего.

В интерфейсе это выглядит убедительно: галочек нет, крестиков нет, значит
порядок.

## Применимость

**Работает** везде, где решение принимается по набору результатов: CI, линтеры,
сканеры уязвимостей, наборы тестов.

Обобщение: **проверяйте мощность множества до проверки его свойств.** «Ноль
найденных проблем» и «сканер не запускался» дают одинаковый отчёт.

Тот же класс — гейты на пустом входе: скрипт, который ничего не нашёл, обязан
отличать «нечего проверять» от «всё проверено и чисто».

**Не работает** там, где пустой набор законен и означает успех: например,
проверка «нет незакоммиченных изменений».
