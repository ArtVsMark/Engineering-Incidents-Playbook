# Производный файл не может быть хранилищем

**Область.** каталог, данные

**Правило.** Данные живут в источнике, из которого производное собирается.
Генератор читает **только источники** и никогда — собственный вывод: иначе
единственным источником значения оказывается его же прошлая копия.

## Инцидент

В указателе каталога была колонка «Область» — предметная классификация: у 124
правил, на двух языках, 51 область. Значение бралось функцией `old_areas()`,
которая разбирала **прежний указатель и собственный вывод** — то есть
производные файлы.

Пока формат строки не менялся, это работало. Указатель переписали: два
одноязычных свели в один двуязычный, и строка таблицы из
`| [001](001-transport-rest-not-graphql.md) | … | квоты, API |` стала
`| 001 | … |`. Регулярка ждала номер в квадратных скобках и перестала совпадать.

Классификация исчезла целиком за одну пересборку. Заметили не сразу и не сами:
о пустой колонке сообщил владелец, увидев её в готовом указателе.

Гейт при этом оставался зелёным, и это главное в инциденте. Проверка
`build_rules_index.py --check` сравнивает сгенерированный текст с лежащим в
репозитории — но пустая колонка была в обоих, и они совпадали. Проверка честно
подтверждала: «указатель актуален», 124 правила. Она сравнивала вывод с выводом,
а данных не было ни там, ни там.

Восстановить удалось только потому, что удалённый файл остался в истории:
`git show 5f429e0^:rules/ru/README.md`. Не будь этого коммита, 51 область
пришлось бы проставлять заново вручную по 124 правилам — то есть придумывать
заново, потому что исходной классификации больше нигде не было.

## Почему

**У производного файла нет автора.** Данные в нём существуют ровно до следующей
пересборки. Когда генератор читает собственный вывод, получается кольцо:
единственный источник значения — его же прошлая копия. Данные держатся на
инерции, и любая смена формата — не ошибка, а молчаливое обнуление.

**Пустота выглядит как значение.** Отсюда неотличимость: колонка на месте,
строки на месте, число правил верное — не заполнено одно поле. Ни один
существующий гейт не мог этого поймать, потому что нечему было расходиться.

Асимметрия цены здесь и определяет форму правила. Прочитать источник и не найти
данных — **громкая** ошибка: файла нет, поля нет, разбор падает. Прочитать
собственный вывод и не найти данных — **тихий** результат: пустое поле, ноль
записей, «просто не заполнено». Первое чинится в тот же час, второе живёт до
случайного взгляда со стороны.

Отсюда починка из двух частей, и одной мало. Перенести данные в источник — в
сами правила. И **сделать отсутствие поля падением сборки**, а не пустой ячейкой
([075](075-a-guard-that-finds-nothing-must-fail.md)): пока пустое значение
допустимо, оно вернётся при следующей смене формата.

## Практические границы

- данные хранятся в том файле, который они описывают, а не в сводке о нём;
- генератор читает источники и **ничего** — из своего вывода, включая прошлые
  версии этого вывода;
- отсутствие обязательного поля — падение сборки с именем файла, а не пустая
  ячейка;
- поле, которое действительно необязательно, объявляется таковым явно — иначе
  пустое значение проходит за данные;
- проверка «собранное совпало с лежащим» не заменяет проверку содержания: она
  сравнивает вывод с выводом.

## Применимость

**Работает** везде, где есть генератор и производный артефакт: указатели,
оглавления, сводные таблицы, витрины, агрегированные отчёты.

**Не работает** для кэша, полностью вычислимого из источника: там производный
файл законно содержит всё, потому что пересборка его восстанавливает. Правило —
про данные, которых **больше негде взять**.

**Признак нарушения:** на вопрос «откуда берётся это значение» приходится
открывать сгенерированный файл.
