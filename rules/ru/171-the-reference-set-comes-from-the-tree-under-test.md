# Эталон берут из дерева самого изменения, а не с общей ветки

**Область.** гейты, конвейер

**Правило.** Эталон, с которым сверяется изменение, берётся из **дерева этого
же изменения**. Эталон с общей ветки приходит из прошлого и делает
неразрешимым ровно тот класс изменений, который сам состав эталона и меняет:
чтобы эталон обновился, изменение должно сначала уехать в общую ветку, а уехать
оно не может — проверка красная. Круг замыкается, и разорвать его можно только
руками, сняв защиту. Признак применимости: проверка сравнивает **состав** —
имена работ, набор файлов, список ключей, — а источник состава лежит вне
проверяемого изменения.

**Переносится вне Claude Code.** да — предмет принадлежит любой проверке
состава: сверке схемы, списку экспортируемых имён, набору обязательных файлов.

## Инцидент

Обязательная проверка ветки у потребителя сверяла имена работ на изменении с
эталоном — именами последнего прогона на общей ветке. Работало, пока состав
матрицы не менялся.

Воспроизведено на подделанных данных: изменение, поднимающее Python с 3.13 на
3.14, даёт имена `гейты · ubuntu-latest · python 3.14`, эталон требует `3.13`,
вердикт — «работы не созданы». И он **вечный**: новые имена попадут в эталон
только после слияния. Контекст проверки обязательный, набор правил без обходов,
то есть единственным выходом осталось бы снять защиту с общей ветки руками.

Ловушка при этом уже была названа в задаче о самой защите — «имена работ
матрицы входят в список обязательных дословно, переименование ломает связь» — и
воспроизвелась этажом ниже, в эталоне.

Починка: спрашивать у площадки прогоны **на голове изменения**, а состав
обязательного читать из `.github/workflows/` того же дерева; сверка идёт по
пути файла, а не по имени работы.

## Почему

Эталон — часть проверяемого, а не внешняя истина. Взяв его с общей ветки,
проверка сравнивает изменение не с его собственным объявлением, а с прошлым
состоянием проекта — и потому верно отвечает лишь на изменениях, которые состав
не трогают.

Класс поломки здесь не «ложное срабатывание», а **самоблокировка**. Обычное
ложное красное снимается правкой изменения; это — не снимается ничем внутри
изменения, потому что требуемое условие достижимо только после слияния. Цена
асимметрична до предела: чтобы провести правку состава, приходится ослабить
защиту, то есть поломка гейта оплачивается снятием гейта.

Отсюда и вторая половина починки — сверять по **пути файла**, а не по имени
работы: имя собирается из параметров матрицы и меняется вместе с ними, путь же
принадлежит дереву и меняется только правкой этого дерева
([049](049-derive-state-from-live-artifacts.md)).

## Практические границы

- состав читают из дерева изменения: `.github/workflows/`, манифест, схема —
  то, что изменение может поправить вместе с собой;
- сверяют по устойчивому ключу — пути файла, а не по имени, собранному из
  параметров;
- у площадки спрашивают **состояние** (прогоны на голове), а не состав: состояние
  внешне по определению;
- внешняя настройка сверяется в обратную сторону — настройка с деревом, а не
  дерево с настройкой ([168](168-one-aggregating-required-check.md)).

## Применимость

**Работает** для проверок состава, которые само изменение вправе менять: имена и
набор работ, список обязательных файлов, ключи схемы.

**Не работает** там, где эталон по существу внешний и изменению не принадлежит:
«версия зависимости не ниже опубликованной», «ответ совпадает с контрактом
издателя». Прошлое там и есть предмет проверки. Не работает и для проверок
состояния — «зелена ли общая ветка»: состояние берут снаружи, иначе оно
перестаёт быть состоянием.

**Признак нарушения:** чтобы проверка позеленела, изменение должно быть сначала
слито.
