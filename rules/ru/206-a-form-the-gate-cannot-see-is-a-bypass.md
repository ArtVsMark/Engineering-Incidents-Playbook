# Форма, которую гейт не видит, становится обходом

**Область.** гейты

**Ступень.** 3 — гейты и процессы

**Правило.** Гейт, ищущий предмет по **форме записи**, обязан читать ВСЕ формы,
которыми этот предмет пишут в его дереве, и набор форм берётся **замером**, а не
перечислением по памяти. Форма, которую гейт не видит, становится обходом — и
обходом не злонамеренным: так пишут по привычке, и потому невидимая форма чаще
всего оказывается самой частой. Если какая-то форма двусмысленна и читать её без
ложных срабатываний нельзя, это объявляется вслух вместе с тем, что гейт
проверяет **не всё**.

**Переносится вне Claude Code.** да — предмет есть у всякой проверки, чей
предмет записывается человеком в свободной форме: линтер по образцу, поиск
секретов, сторож команд, разбор прозы.

## Инцидент

**Свой, живой и дорогой (17.09.2026).** Хук `.claude/hooks/push_guard.py` держит
правило 202 — «слитая ветка воскресает от любого толчка». За одну смену он **не
сработал ни разу из трёх**: ветки были воскрешены толчком после слияния,
конвейер честно открыл изменения на уже слитую работу, и #529 и #531 пришлось
закрывать дублями.

Причина не в проверке воскрешения — она исправна и просто не вызывается. Команда
разбирается так: `re.split(r"&&|\|\||;|\||\n", …)`, и кусок обязан **начинаться**
с `git`. Замер по формам:

```
ВИДИТ | git push
ВИДИТ | cd X && git push
ВИДИТ | git push; echo
 слеп | for i in 1 2; do git push; done
 слеп | while true; do git push; done
 слеп | if true; then git push; fi
 слеп | ( git push )
```

Внутри всякой конструкции оболочки кусок начинается с `do`, `then` или скобки.

**И САМОЕ ДОРОГОЕ: ЦИКЛ ЗДЕСЬ — ФОРМА ПРЕДПИСАННАЯ, НО ПРЕДПИСАНА ОНА НЕ
ДЕРЕВОМ.** Толкать с повтором и откатом велит инструкция САМОГО ОКНА — та, что
приезжает с площадки при его открытии, — а в дереве каталога такого требования
нет ни строки: `grep` по `AGENTS.md`, `CLAUDE.md`, `.claude/settings.json`,
`templates/` и `docs/` даёт НОЛЬ упоминаний повтора толчка. Первая редакция этой
записи приписала предписание дереву, и внешний взгляд показал, что проверить его
командой нельзя — то есть запись требовала от чужих утверждений ровно того, чего
не сделала сама.

Поправка делает довод сильнее, а не слабее: форма пришла оттуда, куда автор
сторожа не смотрит в принципе. Дерево можно перечитать, инструкцию окна — нет, и
потому набор форм, собранный по дереву, здесь неполон ПО ПОСТРОЕНИЮ. Пропуск
оттого и не редкий случай, а норма.

**ПОЧИНЕНО ПО ЗАДАЧЕ #533, И СЧЁТ СТАЛ ДРУГИМ.** Ведущие слова оболочки
снимаются с куска перед разбором, хвосты конструкций тоже: слепых форм из семи
проверенных ноль. Проверено с обоих концов (140) — семь обёрнутых форм видны,
четыре текстовых остаются текстом; полу-откат красит девять тестов. ПОЧИНКА
ПРИНЕСЛА СВОЮ ЛОЖНУЮ СРАБОТКУ, и это часть инцидента: снятие ведущих слов
оживило разрез внутри кавычек, и `echo 'for i in 1; do git push; done'` стал
читаться толчком. Прежде текст в кавычках спасала СЛУЧАЙНОСТЬ — незакрытая
кавычка в куске, на которой спотыкался разбор. Разрез сделан уважающим кавычки
намеренно; защита, державшаяся на случайности, защитой не была.

**Свой, до постройки, а не после поломки.** Замер форм цитирования по всему
дереву: ссылкой `rules/ru/NNN-…` названо **775** упоминаний, голым числом —
**2052**, то есть невидимой формы в **2,6 раза больше**. Гейта цитат у нас нет
вовсе — правило 204 держится документом, — и потому это замер-предупреждение:
гейт, написанный под ссылки, видел бы двадцать семь процентов предмета и зеленел
бы на остальных.

**Замер соседа, из которого пришло предложение** (проект механизмов): гейт
применимости цитат читал одну форму — ссылку. Голый номер в скобках цитатой не
считался. Утверждение, написанное ссылкой, гейт нашёл и его исправили; близнец
того же утверждения, написанный числом, прожил ещё шесть дней, говоря обратное.
Замер по их дереву: **1007** упоминаний ссылками против **1744** голым числом, и
**23** правила названы ТОЛЬКО голым числом. Расширение формы нашло пять живых
цитат неприменимых правил: один настоящий дефект, один хвост правки того же дня и
три законных упоминания границы. Проверено откатом: прежний гейт при живом
дефекте зелёный.

## Почему

**Невидимая форма — самая частая, и это не совпадение.** Гейт пишут под ту форму,
которую автор гейта держит в голове в момент письма. В дереве пишут иначе: так,
как короче и привычнее. Два замера из трёх дали перевес невидимой формы в два с
половиной раза, третий — предписанную форму в слепой зоне.

**Обходящий не знает, что обходит.** Это отличает предмет от обхода
злонамеренного: некого учить и нечего запрещать. Лечится только расширением
охвата либо названной границей.

**Зелёный при живом дефекте неотличим от зелёного при чистоте.** Гейт с
двусторонним набором подтверждает, что механизм работает как объявлен (146), — но
объявлен он был для одной формы. Набор мутаций этого не ловит: он пишется в тех
же формах, что и гейт.

**Перечень форм по памяти устаревает молча.** Он есть рукописное знание о дереве
и живёт до первой правки соседа. Замер — не оформление, а источник: он должен
лежать рядом с гейтом и пересниматься при расширении.

## Практические границы

- набор форм берётся ЗАМЕРОМ по дереву, и замер кладётся рядом с гейтом числом,
  а не словами «все известные формы»;
- форма, которую нельзя читать без ложных срабатываний, объявляется вслух вместе
  с охватом: «гейт проверяет не всё, и вот чего именно он не видит» — молчаливая
  граница, известная только автору гейта, и есть дефект;
- двусмысленность снимается СУЖЕНИЕМ формы, а не отказом от неё: у соседа голый
  номер стал читаться только не приклеенным к имени и только из своего реестра —
  иначе цитатами становились коды ответа площадки;
- при расширении формы гейт проверяется откатом: прежний обязан быть зелёным на
  живом дефекте, иначе расширение ничего не изменило;
- «читает все формы» не значит «читает любой текст»: строка-аргумент для другой
  программы формой не является, и сторож смотрит на действие, а не на вхождение
  слова.

## Применимость

**Работает** для гейтов, чей предмет записывается человеком в свободной форме:
команда оболочки, цитата, ссылка, маркер в прозе, образец в коде.

**Не работает** там, где предмет задан ИМЕНЕМ в пространстве имён — там разрешать
надо по импортам, и это [180](180-a-gate-resolves-the-call-not-the-last-name-segment.md),
а не перечень форм. Не работает и там, где форма ровно одна по построению:
машинно порождённый файл, строгая схема, поле реестра. Там перечень форм
выродится в единицу, и замер станет обрядом.

**Признак нарушения:** перечень форм в гейте вписан руками, а рядом нет числа —
сколько какой формы в дереве.
