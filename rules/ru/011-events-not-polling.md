# Наблюдение: событие вместо опроса, а если опрос — то условный

**Область.** квоты, наблюдение

**Ступень.** 2 — конвейер и CI

**Правило.** Цикл наблюдения — самый дорогой режим работы с API. Подписка
предпочтительнее опроса; опрос — только условный и только по дельте.

## Инцидент

Наблюдение за очередью PR в цикле выжигало квоту быстрее любой другой работы.
Арифметика простая: шесть открытых PR дают **семь и более вызовов за проход**
(список плюс заход внутрь каждого). Раз в минуту — под тысячу вызовов в час.

При этом почти все ответы одинаковы: в PR ничего не менялось.

## Что снижает цену — по убыванию эффекта

- **Подписка вместо опроса.** Если среда даёт события об активности, наблюдатель
  обязан их использовать: они приходят **без единого запроса**. Опрос —
  резервный вариант, а не основной.
- **Условные запросы (`ETag` / `If-None-Match`).** Ответ `304 Not Modified`
  **не расходует лимит**. Пока объект не менялся, опрос бесплатен.
- **Дельта вместо полного обхода.** Список с сортировкой по времени изменения;
  заходить внутрь только к тем, у кого оно сдвинулось.
- **Интервал в минутах, а не в секундах**, и он растёт с каждым дополнительным
  наблюдателем: квота общая на аккаунт.

## Почему

Опрос платит за **отсутствие изменений** — то есть за самый частый исход. Все
четыре приёма бьют в одну точку: не платить, когда ничего не произошло.

Дополнительный довод против дорогого транспорта: у GraphQL нет механизма
условных запросов. В цикле это делает его непригодным принципиально, а не
«дороговато».

## Применимость

**Работает** для любого мониторинга поверх HTTP API с лимитами.

**Не работает**, если у API нет ни событий, ни `ETag` — тогда остаются дельта и
интервал.

**Не относится** к CI: там свой токен с отдельным лимитом.
