# Код с экранированием писать файлом, а не heredoc'ом

**Область.** инструменты

**Правило.** Escape-последовательности проходят через оболочку и меняются.
Файл — единственный надёжный носитель.

## Инцидент

Строка `\n` внутри Python-кода, записанного через bash-heredoc, **дважды**
превратилась в настоящий перевод строки. Результат:

```
SyntaxError: unterminated string literal
```

Диагностика заняла время именно потому, что исходный текст выглядел
правильным: ошибка возникала на пути от текста к файлу, а не в самом коде.

## Почему

Heredoc — это не «вставить текст как есть». Между вашими символами и файлом
стоит оболочка, и она интерпретирует то, что считает своим: экранирование,
подстановку переменных, продолжение строк.

Часть поведения зависит от того, закавычен ли разделитель (`<<EOF` против
`<<'EOF'`), а часть — от самой оболочки. То есть один и тот же текст в разных
окружениях даст разный файл.

## Применимость

**Работает** для любого генерируемого кода, содержащего `\n`, `\t`, `\\`,
`$`, обратные кавычки — то есть почти для всего, кроме простой прозы.

**Не работает** как запрет heredoc вообще: для текста без экранирования он
удобен, и закавыченный разделитель снимает большую часть рисков.

**Обобщение:** любая передача текста через промежуточный интерпретатор — риск
незаметной подмены. Чем меньше слоёв между источником и файлом, тем меньше
поводов для сюрприза.
