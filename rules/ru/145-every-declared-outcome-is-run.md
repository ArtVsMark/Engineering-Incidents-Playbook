# Механизм, объявивший несколько исходов, прогоняется по каждому

**Область.** гейты, прогоны

**Правило.** Механизм, у которого объявлено больше одного исхода, проверяется
прогоном **каждого** из них, а не только успешного. Прогон одного пути
подтверждает, что механизм запускается, — и ничего больше. Необъявленные ветки
при этом обычно не «работают неверно», а **не существуют**: код, до которого не
доходит управление, читается как рабочий и переживает любое чтение.

## Инцидент

Оболочка шага объявляет три исхода и разбирает код возврата:

```bash
set -uo pipefail
python scripts/sync_labels.py
rc=$?
if [ "$rc" -eq 2 ]; then exit 1; fi     # механизм не отработал
if [ "$rc" -eq 1 ]; then echo "::warning::…"; fi   # находка для человека
exit 0
```

Читается безупречно. Работает на одном исходе из трёх.

Площадка зовёт шаг как `bash -e {0}`, и `set -uo pipefail` этот `-e` **не
снимает**. На ненулевом коде оболочка умирает раньше, чем `rc` присвоится:
разбор стоит за строкой, до которой управление не доходит. Исход 1 —
«есть незаявленные метки», по замыслу находка, а не поломка, — ронял прогон
наравне с отказом.

Три места за один день, одна форма:

| место | цена |
|---|---|
| `labels-sync.yml` | первый же прогон красный, механизм не работал **ни дня**; замечено на четвёртый |
| корневое `action.yml` | краснели прогоны **чужих** проектов, подключивших действие |
| `main-red.yml` | объявлено два исхода, прогонов было **ноль**; на первом же нашлось настоящее красное |

Мутация показала цену точно:

```
скрипт вернул   было    стало
0                0       0
1                1  ✗    0 + warning
2                2  ✗    1
```

На исходе 1 старая оболочка давала **ложный отказ**, на 2 — даже не тот код.

## Почему

Успешный путь прогоняется сам собой: его проходит любой обычный запуск. Все
остальные ветки существуют только в голове автора, пока их не выполнили. Разница
между «ветка неверна» и «ветки нет» невидима при чтении — обе выглядят как код.

Отсюда же обратная ошибка, которую ловит тот же приём: ветка может **отвергать
законное**. Односторонний набор её не видит, потому что смотрит только на то,
что механизм обязан отвергнуть ([097](097-a-checker-has-two-error-types.md)).

Двух соседних правил здесь **не хватает**, и это стоит сказать прямо.
[139](139-a-mechanism-is-confirmed-by-a-run.md) требует прогона вместо чтения —
и удовлетворяется одним успешным прогоном, то есть ровно тем, что было во всех
трёх случаях: `labels-sync` прогонялся и краснел, действие прогонялось у чужих
проектов. [140](140-a-gate-is-tested-by-what-it-must-reject.md) требует прогнать
путь отказа — но говорит про **гейт**, а оболочка шага, работа по расписанию и
действие для потребителя гейтами не являются.

Новое здесь третье: объявленная ветка может быть **недостижимой**. Не «неверной»
— недостижимой, и тогда её отсутствие неотличимо от исправности ни чтением, ни
успешным прогоном.

## Практические границы

- прогоняется **объявленное**, а не воображаемое: список исходов берётся из того,
  что механизм сам о себе говорит — из кода, комментария или документа;
- исход «механизм не отработал» проверяется отдельно от «есть находки»: их
  склейка и есть самая частая пропажа ([039](039-three-outcomes-not-two.md));
- прогон на подделке засчитывается, но живой предмет сильнее: подделку строит
  тот же, кто ошибся ([139](139-a-mechanism-is-confirmed-by-a-run.md));
- если исход нельзя прогнать сегодня — это записывается, а не откладывается
  молча ([046](046-name-the-gaps-do-not-level-them.md)).

## Применимость

**Работает** везде, где исходов больше одного и они названы: гейты, шаги
конвейера, действия для потребителей, разбор кодов возврата, обработка отказов.

**Не работает** там, где исход один по построению — команда без ветвления, чистая
трансформация без отказов. Прогонять «каждый из одного» нечего, и требование
выродится в обряд.

**Признак нарушения:** в механизме есть ветка, о которой нельзя сказать, когда
она последний раз выполнялась.
