# Смена правил работы — повод перезапустить окна, а не рассылка

**Область.** агентские сессии

**Правило.** Изменили правила, по которым работают окна, — перезапускаете окна.
Возраст окна тут ни при чём: правило меняется событием, а контекст читается один
раз, при старте.

## Инцидент

Транспорт к внешнему API сменили на дешёвый: старый способ жёг квоту, новый —
нет. Правило записали в главный файл проекта, инструмент дорос до полного
покрытия, документацию обновили. Всё сделано верно.

Квоту продолжали выжигать. Причина нашлась по датам: одно окно стартовало
**шестью днями раньше** правки и работало по инструкциям, актуальным на момент
своего запуска. Окна, созданные позже, ходили по-новому — то есть правило
работало, но только для тех, кто родился после него.

Снаружи это неотличимо от саботажа: окно не спорит, не жалуется и уверенно
делает по-старому.

## Почему

Правила проекта попадают в окно **один раз** — когда оно читает их при старте.
Дальше файл может меняться сколько угодно: у уже запущенного окна остаётся
снимок той эпохи, в которую оно родилось.

Отсюда несимметричность, которую легко упустить: **правка документа действует на
будущие окна и не действует на текущие**. Написать правило — половина работы;
вторая половина — довести его до тех, кто уже работает.

Просто «сказать в чат» помогает частично и ненадёжно: указание конкурирует с
накопленным контекстом, где то же самое написано иначе, и проигрывает тем чаще,
чем старше окно. Перезапуск снимает конфликт целиком.

## Практические границы

- перезапуск обязателен, если менялись: транспорт и способ ходить наружу,
  запреты, границы ролей, порядок мержа, формат артефактов;
- необязателен, если менялось содержание задач: их окно и так читает заново;
- порядок — **сначала правка, потом перезапуск**, иначе новое окно снова
  прочитает старое;
- в стартовом сообщении нового окна изменившееся правило называется прямо, а не
  подразумевается «оно же в файле»;
- пока окна не перезапущены, наблюдаемое поведение сравнивают **по дате старта
  окна**, а не по дате правки правила: иначе диагноз уйдёт в сторону.

## Применимость

**Работает** для любых агентов, читающих конфигурацию или свод правил при старте.

**Не работает**, если правила перечитываются перед каждым ходом, — тогда достаточно
правки.

**Признак проблемы:** новое правило соблюдают одни окна и не соблюдают другие,
и граница проходит ровно по дате их создания.
