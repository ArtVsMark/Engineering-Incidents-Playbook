# Агенты возвращают данные — файлы правит хост

**Область.** параллельная работа

**Правило.** Параллельные исполнители отдают результат, а не пишут в общее
дерево. Запись — за одним.

## Инцидент

Волна параллельных агентов, каждый со своей задачей, правила файлы напрямую.
Результат предсказуем задним числом: перезаписи, потерянные изменения,
состояние дерева, которое невозможно объяснить.

## Почему

Параллельная запись в общий ресурс без синхронизации — гонка. Агенты не видят
друг друга, и «сначала прочитал, потом записал» у двоих даёт потерю одного из
результатов.

Хуже того, поломка **не воспроизводится**: она зависит от того, кто успел
раньше, и в следующий раз может не повториться.

Разделение снимает проблему целиком: исполнители работают параллельно и
возвращают структурированный результат; хост применяет изменения
последовательно, видя всю картину и разрешая пересечения.

Побочная выгода — результат каждого агента становится **данными**: его можно
проверить, показать, сохранить в журнал. Правка «на месте» такой возможности не
оставляет.

## Применимость

**Работает** для любой параллельной обработки с общим состоянием: агентные
волны, воркеры, распределённые сборки.

**Не работает**, если исполнители изолированы по-настоящему — например, каждый в
своей копии дерева. Тогда конфликт разрешается на слиянии, а не при записи.

**Цена:** результат надо уметь описать данными. Для правок кода это диффы или
структурированные находки, а не «я поправил».
