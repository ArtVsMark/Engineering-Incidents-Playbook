# Агентское окно живёт три–пять дней

**Правило.** Долгоживущая сессия дорожает и консервирует устаревшие правила.
Дальше срока — перезапуск с передачей эстафеты.

## Инцидент

Замер по живым сессиям одного проекта:

| Окно | Дней | Чтения кэша на 1 токен выхода | Стоимость |
|---|---:|---:|---:|
| самое старое | 7 | **764** | $392 |
| среднее | 4 | 650 | $106 |
| созданное заново | 1 | **81** | $6 |

**Одно недельное окно потребило больше, чем пять остальных вместе взятых** —
$392 против $335.

Оно же оказалось источником второй проблемы: выжигало квоту GitHub API,
обращаясь по дорогому транспорту. Причина выяснилась по датам: окно стартовало
13-го числа, а инструмент дешёвого транспорта дорос до полного покрытия 19-го.
Окно работало по инструкциям, актуальным **на момент своего запуска**.

Обновлённые правила проекта до него не дошли: контекст читается один раз при
старте.

## Почему

Каждый ход перечитывает весь накопленный контекст, поэтому **цена одного и того
же результата растёт вместе с возрастом окна**. Контекст только накапливается,
сам он не уменьшается.

Второй эффект тоньше и опаснее: **правка документации задним числом не
действует на уже запущенные окна**. Долгоживущая сессия живёт правилами той
эпохи, в которую родилась, и внешне это никак не проявляется.

## Как передавать эстафету

Стартовое сообщение нового окна: как работаем → где остановились → решения,
которые не отменяются → ссылки на задачи.

**Контекст передаётся ссылками, а не пересказом.** Пересказать подробности в
стартовом сообщении — значит перенести проблему вместе с эстафетой: новое окно
сразу получит раздутый контекст.

## Применимость

**Работает** для любых долгоживущих агентских сессий с накоплением контекста.

**Не работает** там, где контекст не растёт: одноразовые задачи, сессии с
принудительным сжатием.

**Оговорка:** возраст — не единственный фактор. Окно, работающее с кодом, читает
больше, чем окно обсуждения. Но контекст не уменьшается сам, поэтому старое
окно дорогим становится неизбежно.
