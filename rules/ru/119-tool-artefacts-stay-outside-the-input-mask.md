# Свои артефакты держат вне маски входа

**Область.** код, данные

**Правило.** Файлы, которые создаёт инструмент, называются так, чтобы **не
попасть под его же правило отбора входов**. Иначе он начинает обрабатывать
собственный вывод.

## Инцидент

Инструмент отбирает файлы решений по образцу имени. Отдельно он сохраняет
историю отправок: код каждой попытки рядом с описанием исхода.

Имена файлов истории заданы **намеренно вне** образца отбора. Не по стилю, а по
последствию: попади они под образец, старые попытки пришли бы в режимы сравнения
как полноправные конкуренты. Сравнение решений превратилось бы в соревнование
пользователя с собственным прошлым — с тем отличием, что он об этом не знает.

Тот же приём в соседнем месте: сторож побочных эффектов исключает из проверки
файлы, которые пишут инструменты самого прогона, — иначе он обвиняет тесты в
том, что натворила измерительная оснастка.

## Почему

Инструмент, чей вывод попадает в его же вход, замыкается сам на себя. Результат
не выглядит ошибкой: он выглядит **правдоподобно**, просто описывает не то, что
думает пользователь. Обнаруживается это по странностям в цифрах, а не по отказу.

Правило отбора при этом обычно писалось раньше, чем появился вывод, — и
конфликта не было, пока инструмент не начал что-то сохранять. То есть дефект
возникает **при добавлении функции**, а ломается совсем другая, давно
работающая.

Отсюда проверка при каждом новом артефакте: **попадёт ли он под какие-либо
существующие правила отбора** — свои и чужие: сборка, поиск, индексация,
резервное копирование.

## Практические границы

- служебные файлы отличаются от пользовательских **на уровне имени или
  каталога**, а не только по расширению;
- отделение задокументировано вместе с причиной: без неё следующий приведёт
  имена «к единообразию»;
- если разделить именами нельзя, отбор ведётся по явному списку, а не по
  образцу;
- добавляя артефакт, проверить и чужие правила отбора: игнор-списки, шаблоны
  сборки, маски резервного копирования.

## Применимость

**Работает** для инструментов, которые и читают, и пишут в одном каталоге:
сборщики, проверяющие, конвертеры, индексаторы.

**Не работает**, если вывод по замыслу становится входом следующего прогона, —
там нужен явный признак поколения, а не разделение имён.

**Признак проблемы:** число обработанных единиц растёт от прогона к прогону без
внешних изменений.
