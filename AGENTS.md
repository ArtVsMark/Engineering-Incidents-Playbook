# Каталог правил — ядро для любого агента

> **Читатель:** агент — что каталог требует от любого агента.

> Это ядро: что каталог требует от **любого** агента, работающего в этом
> репозитории, независимо от того, чем он запущен. Надстройка для агентского
> окна Claude Code — [`CLAUDE.md`](CLAUDE.md); документ для человека со
> стороны — [`CONTRIBUTING.md`](CONTRIBUTING.md). Разные читатели — разные
> документы ([021](rules/ru/021-split-docs-by-reader.md)).

**Здесь действует весь каталог, а не только процитированное ниже.** Указатель —
[`rules/README.md`](rules/README.md), вход по предмету — раздел «По областям».
Ядро называет поимённо лишь то, что нарушается чаще всего; остальное окно
обязано найти само, и «в своде не было» причиной не считается
([134](rules/ru/134-a-window-reopens-only-after-the-rulebook-exists.md)).

**Формат правила один:** правило → инцидент → почему → применимость → след.
«Применимость» отвечает, где правило **не** работает; «След» обязателен, без
него запись не проверить, и связь с проектом собирается именно из него
([120](rules/ru/120-how-to-run-a-rule-catalogue.md)).

## 🚦 Критические запреты

```
❌ НЕ править rules/README.md, export/rules.json, .github/badges/* руками —
   это производные файлы, их пересобирает scripts/build_rules_index.py
❌ НЕ править export/where.* руками — это сводка ответов потребителей,
   её пересобирает scripts/aggregate_bindings.py
❌ НЕ добавлять правило только на одном языке — сборка не пройдёт, и это
   не придирка: так деревья и расходятся
❌ НЕ переиспользовать номер правила, даже после удаления
❌ НЕ править правило задним числом при пересмотре — пересмотр это НОВАЯ
   запись, старая помечается строкой «Заменено.» с номером смены
❌ НЕ вписывать числа в прозу без маркера и сборки, которая их переписывает
❌ НЕ коммитить без трейлеров авторства — гейт отвергает чужое имя и след
   сессии без соавторства; коммит вовсе без подписи он считает и печатает
   числом. Так измерено, а не задумано (scripts/check_gates.py)
❌ НЕ везти в одном изменении две темы. Сборное изменение можно сделать
   честным, объявив все закрываемые задачи, но нельзя сделать разбираемым:
   его не отревьюить, не откатить и не найти по частям (132)
```

**Про последний запрет — почему у него нет гейта, и это решение.** Число
тронутых зон сборности НЕ доказывает: правка одного правила законно трогает
`rules/ru`, `rules/en`, указатель, экспорт и сводку — пять зон и одна тема. А
ложный отказ на широкой теме дороже пропуска: он приучает читать красное как
фон ([051](rules/ru/051-warn-on-likely-block-on-certain.md)). Само правило
требует **предупреждения**, а не отказа, — и предупреждение есть: шаг «кто ещё
правит те же файлы» в `agent-pr.yml` пишет пересечения в сводку работы, не
блокируя ([133](rules/ru/133-file-overlap-sets-the-boundary.md)).
Разбирает их человек.

**Признак, что запрет нарушен, и он читается, а не считается:** заголовок
изменения не описывается одной строкой без союза «и».

## 🛡 Гейты

Стоят в `.github/workflows/ci.yml`, запускаются локально, и все обязаны быть
зелёными до слияния:

| Команда | Что держит |
|---|---|
| `python scripts/build_rules_index.py --check` | указатель, области, словарь, следы, экспорт, значки |
| `python scripts/check_links.py` | локальные ссылки и якоря |
| `python scripts/check_attribution.py` | трейлеры против `.github/authors.txt` |
| `python scripts/collect_changelog.py --check` | форма фрагментов журнала |
| `python scripts/check_bindings.py` | ответ каталога по каждому правилу + метрика |
| `python scripts/aggregate_bindings.py --check` | сводка «где действует» собрана из ответов потребителей |
| `python scripts/audit_catalogue.py` | содержание записи: утверждение, граница «не работает», разрешимый след, паритет разделов |
| `python scripts/check_charter.py` | этот свод и `CONTRIBUTING` называют те же гейты, что стоят в конвейере |
| `python scripts/check_duplicates.py --check` | у нового правила спрошено о соседях — вопрос задан, решение за человеком |
| `python scripts/collect_proposals.py --check` | вердикт по правилам, приехавшим из проектов: принято под каким номером, отклонено почему |
| `python scripts/check_candidates.py` | кандидаты не притворяются правилами, и ни одно правило на них не ссылается |

| `python scripts/check_showcase.py` | витрина отвечает на весь объявленный набор вопросов либо называет, чего нет и почему |
| `python scripts/check_test_deps.py` | каждый импорт тестов объявлен, а не случайно установлен у автора |
| `python scripts/check_task_state.py --selftest` | состояние задачи после слияния судится верно: закрытая закрыта, частичная несёт остаток |
| `python scripts/check_subprocess.py` | текстовый вызов наружу называет кодировку, а не берёт её у окружения |
| `python scripts/check_third_outcome.py` | третий исход называет ПРЕДМЕТ отказа, а не только причину: «не отработала» без адреса неотличима от «сломалось что-то» |
| `python scripts/check_schedules.py` | темп прогона по расписанию выведен из бюджета арифметикой, а роль его объявлена: у страховки обязан быть замер |
| `python scripts/check_forgeries.py` | у набора, подменяющего шов наружу, назван АДРЕС, по которому подделка сверяется с настоящей стороной |
| `python scripts/check_text_cuts.py` | разрез строки по точке помечен «не проза: <что именно>»: контекст человеческого текста берут абзацем |
| `python scripts/check_python_version.py` | планка `requires-python`, версия каждого прогона и версия ЗАПУСТИВШЕГО прогон перед толчком — одно и то же число |
| `python scripts/check_exclusive.py --check` | у верхних пар исключительных утверждений («только X») есть вердикт: два таких утверждения об одном предмете запрещают друг друга |
| `python scripts/check_labels.py` | зона изменения выведена из тронутых путей и стоит на нём |
| `python scripts/check_workflows.py` | у каждого прогона ручная кнопка, у каждой работы предел времени |
| `python scripts/check_templates.py` | каждая заготовка сказала, чем она применяется у самого каталога |
| `python scripts/check_connect.py` | вход в проект называет каждый отданный наружу инструмент, и все они существуют |
| `python scripts/check_readers.py` | у каждого документа назван читатель из закрытого словаря, и у каждого читателя есть документ |
| `python scripts/check_locale.py` | английское дерево переведено, а не скопировано: сверяется язык, а не структура |
| `python scripts/check_skips.py` | пропущенный тест называет причину, иначе он неотличим от забытого |
| `python scripts/check_verdict_order.py` | вердикт набора и гейта выносится после последнего случая, а ранний выход — только третьим исходом |
| `python scripts/check_own_name.py` | каталог назван одним именем, и оно сверено с адресом `origin`, а не с самим собой |
| `python scripts/check_roles.py` | у каждой роли карты направлений своё возражение, и его адресат — другая роль этой же карты |
| `python scripts/check_prose.py` | сворачиваемых блоков в тексте нет, версия в манифесте не вписана |
| `python scripts/history_metrics.py --check` | у каждого выпуска есть строка эволюции метрик, и её числа сверены с деревом тега |
| `python scripts/check_gates.py` | гейты отвергают то, что обязаны, **и пропускают то, что обязаны** |
| `python scripts/main_red.py --selftest` | дежурный по общей ветке: свёртка по имени, исключения, три исхода |
| `python scripts/link_trails.py --selftest` | обратная ссылка: свои следы против чужих, идемпотентность, три исхода |
| `python scripts/refresh_derived.py --selftest` | пересборка производных: свежие данные · поломка сборщика · правка человека — и что из этого коммитится без человека |
| `python scripts/pr_body.py --check` | изменение закрывает задачу словом в теле либо освобождено строкой с причиной |

**Значков в этом списке нет намеренно.** Все они живут на отдельной ветке
`badges`, в дереве общей ветки их нет, и свежесть держит `badges.yml` на
каждый толчок в `main`. Гейт свежести значка требовал пересборки от каждого
изменения и краснел на верной работе — а такую проверку приучаются пропускать
([051](rules/ru/051-warn-on-likely-block-on-certain.md)).

Отдельно от них — проверка **уже слитого**, в `attribution-history.yml`:

| Команда | Что держит |
|---|---|
| `python scripts/check_attribution.py --first-parents` | атрибуция в первопредках `main` |

Она стоит не в `ci.yml` и в обязательные проверки ветки **не ставится**: её
красное означает долг прошлой истории, который правкой изменения не чинится.
Работа с условием внутри `ci.yml` дала бы на изменениях исход `skipped`, а такое
изменение площадка чистым не считает — и автомерж ему включить нельзя.

У проверки **три исхода**, а не два: чисто · есть находки · **не отработала**.
Третий различается кодом `2` ([039](rules/ru/039-three-outcomes-not-two.md)).

## ✍️ Как добавить правило

**Каркас собирает `scripts/new_rule.py`, а не рука.** Номер, оба дерева,
область, след, ответ каталога, фрагмент журнала, вопрос о соседях — всё
механическое одной командой. Остаётся суждение: утверждение, инцидент,
граница «не работает». Предложение из проекта — тем же скриптом,
`--from-proposal владелец/репозиторий:слаг`; номер присваивает каталог.

Ниже — что именно он делает, чтобы это можно было проверить и сделать руками.


0. **Спросить каталог, нет ли уже такого** — `check_duplicates.py --near`,
   **до** того как запись написана. 143 переоткрыло сказанное 131 и 135, и
   было удалено; искали бы — не написали бы. Ответ ложится в
   `.rules/neighbours.json`, гейт проверяет, что он есть, но **не** решает,
   дубль это или нет: порога у метрики нет, и это измерено.
1. Номер следующий свободный, имя латиницей: `NNN-короткий-слаг.md`.
2. **Оба дерева сразу**, `rules/ru/` и `rules/en/`, имя файла одинаковое.
3. Строка `**Область.**` / `**Area.**` из словаря в `scripts/build_rules_index.py`.
4. Раздел «След», который **разрешается**: задача `владелец/репозиторий#номер`
   либо потребитель из `.rules/consumers.json` с названным артефактом. Проза
   следом не считается — это проверяет `scripts/audit_catalogue.py` (#68).
5. **Закоммитить правило**, потом пересобрать:
   `python scripts/build_rules_index.py`. Порядок именно такой — дата
   появления берётся из истории файла, и до коммита её нет.
6. Ответ о самом каталоге в `.rules/bindings.json` — статус по новому правилу.
7. Пересобрать сводку: `python scripts/aggregate_bindings.py` — таблица «где
   действует» перечисляет правила поимённо и без этого отстанет на одно.

Заготовка — [`templates/rule-template.md`](templates/rule-template.md).
Полностью — [`120`](rules/ru/120-how-to-run-a-rule-catalogue.md).

**Правило без инцидента в каталог не идёт:** это предпочтение, а не правило.

## 📌 Коммит, журнал, метки

**Трейлеры** в каждом коммите — сверяются с `.github/authors.txt`
([123](rules/ru/123-attribution-is-verified-on-the-final-history.md)):

```
Co-Authored-By: <имя агента> <почта агента>
Claude-Session: <ссылка на сессию, если она есть>
```

**Журнал** — фрагментом в `changelog.d/<слаг>.<секция>.md`, не строкой в общий
файл ([030](rules/ru/030-changelog-from-fragments.md)).

**Метки** — из `.github/labels.yml`, зоны по артефактам каталога
([064](rules/ru/064-labels-are-machine-input-not-decoration.md)). Ставит их
конвейер по тронутым путям, а `scripts/check_labels.py` сверяет: метит машина,
потому что инцидент правила измерен так — «машина метила исправнее человека».

**Кто именно подписывает и кто открывает изменение — не здесь.** Это свойство
конкретного окна, а не каталога, и живёт в надстройке
([135](rules/ru/135-session-identity-is-established-by-a-write.md)).

## 🗺 Карта направлений

Имя называет **вопрос**, а не должность. Непокрытое записано как непокрытое —
это требование [082](rules/ru/082-roles-must-cover-every-layer.md), а не
самокритика: незаданный вопрос не оставляет следа, и дыра в составе не
обнаруживается чтением списка.

Артефакты берутся из зон `.github/labels.yml`, а не перечисляются заново: две
классификации одной территории расходятся молча ([022](rules/ru/022-one-canonical-document.md)).

| Направление | Вопрос | Возражение — и кому | Зона · артефакт | Покрыто |
| --- | --- | --- | --- | --- |
| Автор правил | что за инцидент и где границы | Инженер гейтов — «под пересказ гейт держит не то: в записи нет инцидента, и признак взят из формулировки, а не из поломки» | `area/rules` · `rules/**` | да |
| Хранитель корпуса | не пишем ли второй раз то, что уже записано | Автор правил — «это не новая запись, а второй инцидент к существующей: номер не занимай, номера не переиспользуются» | `area/rules` · `rules/**`, `.rules/neighbours.json` | частично: `check_duplicates.py` требует ответа о соседях, но **дубль не судит** — порога у метрики нет, законные пары ближе живого дубля (замер на удалённом 143) |
| Инженер гейтов | чем это держится машинно | Автор правил — «признак, который ты назвал, машине недоступен: переформулируй предмет или признай, что механизма не будет» | `area/gates` · `scripts/*`, `.github/workflows/*` | да |
| Редактор витрины | дочитают ли это | Хранитель свода — «верно и нечитаемо: до нужного места читатель не дойдёт, а непрочитанное правило не работает» | `area/showcase` · `README*`, `START`, `TOP-10`, `HISTORY`, `changelog.d/**` | частично |
| Ревизор | сходится ли объявленное с фактическим | Инженер гейтов — «ответ называет адрес, которого на диске нет: декларация не сверена с фактом» | `.rules/bindings.json`, метрики | частично: `check_bindings.py` сверяет декларации с фактом |
| Контракты | как это сломается у чужого потребителя | Инженер гейтов — «у нас работает, у потребителя нет: механизм завязан на наш путь, наш токен или нашу зону» | `area/export` · `export/**` | частично: `aggregate_bindings.py` роняет сборку на нечитаемом ответе объявленного потребителя |
| Хранитель заготовок | не разъехалась ли заготовка с тем, что мы делаем сами | Инженер гейтов — «правку нельзя вносить, пока заготовка не догонит: её берут другие проекты» | `area/templates` · `templates/**` | да: `audit_catalogue.py` сверяет заготовку правила с каноном разделов, утверждением и границей |
| Хранитель свода | сходится ли **этот файл** с тем, что делает конвейер | Инженер гейтов — «свод называет гейт, которого в конвейере нет, либо конвейер держит то, о чём свод молчит» | `CLAUDE.md`, `CONTRIBUTING.md` | да: `check_charter.py` — объявленные гейты сверяются с шагами `ci.yml` |
| **Локализация** | то же ли это по-английски | Автор правил — «по-английски это другое утверждение, а не то же: совпадение разделов переводом не является» | `rules/en/**` | **нет**: сверяются имена, разделы и следы, но не перевод ([077](rules/ru/077-key-parity-is-not-translation.md)) |
| **Диспетчер** | что без метки, что без ответа, что стоит | Хранитель свода — «работа названа, а источника у неё нет: ни задачи, ни метки, ни адресата» | трекер | **нет** |
| Дежурный по общей ветке | зелена ли `main` **прямо сейчас** | **Диспетчер** — «очередь двигается на сломанном основании: зелёное здесь значит лишь, что хуже не стало» | вкладка прогонов | да: `main-red.yml` заводит **одну** задачу, пока общая ветка красная — трекер и есть то место, куда окно смотрит обязательно ([091](rules/ru/091-work-sources-are-ordered-first-non-empty-wins.md)) |
| **Критик гипотезы** | проверено ли прогоном **то утверждение**, ради которого написана запись | Инженер гейтов — «гейт зелёный и подтверждает себя, а не утверждение, ради которого построен» | `rules/**` против замера | **нет**: гейт можно построить безупречно и вокруг ложной причины. Так и вышло с 143: набор подделок был зелёным, гейт работал, а держал он не то |
| Привлечение | как сюда попадает новый человек | Редактор витрины — «новичок здесь останавливается: дальше нужен контекст, которого у него ещё нет» | `CONTRIBUTING.md` | частично: документ есть и двуязычен; что новичок по нему дойдёт, не проверяется ничем ([065](rules/ru/065-the-onramp-must-speak-the-newcomers-language.md)) |
| Критик метода | проверяет ли проверка то, что надо | **Критик гипотезы** — «замер сделан на подделке, а вывод сделан о живом: предмет проверки подменён» | тесты гейтов | частично: `check_gates.py` прогоняет по подделке атрибуцию, полноту записи и сборку указателя — с обеих сторон, ложное «прошло» и ложный отказ; остальные гейты проверяются только зелёным прогоном |

**Чем это уже стоило.** Самоаудит каталога провёл владелец, а не механизм:
семь нарушений собственных правил нашлись по его вопросу. Это и есть цена
непокрытого «ревизора» — вопрос был не задан никем. Часть его работы теперь
делает `check_bindings.py`: он сверяет заявленное в ответе с тем, что есть на
диске, и первым же прогоном нашёл четыре расхождения, накопившихся за сутки.

**Чем стоили два новых непокрытия — в одном окне.** «Дежурный»: ежедневный
отказ простоял четыре дня, и заметил его владелец. «Критик гипотезы»: запись
143 была написана по чтению конвейера, гейт под неё построен и зелён, а
утверждение оказалось ложным — замер по шести изменениям показал, что решает
не подпись коммитов. Обе находки принадлежат владельцу, а не механизму, и обе
были доступны любому, кто задал бы вопрос вслух.

Общее у них: **окно проверяло свою работу, а не своё утверждение.** Гейты
зелёные, подделки проходят, ссылки целы — а то, ради чего всё делалось, ни разу
не прогонялось на живом предмете ([139](rules/ru/139-a-mechanism-is-confirmed-by-a-run.md)).

Направление становится отдельной ролью, только если у него **своё возражение**
([062](rules/ru/062-a-role-must-be-able-to-object.md)); пока его нет, покрытие
записывается профилем существующей. «Хранитель заготовок» приёмку проходит: его
возражение адресовано инженеру гейтов — «правку нельзя вносить, пока заготовка
не догонит, её берут другие проекты».

## 🔬 Границы прохода

**На шаге сбора ничего не разбирается**
([054](rules/ru/054-collect-and-analyse-are-separate-passes.md)). Прогнать, записать
сырое, идти дальше; разбор — отдельным проходом, на границе естественной
единицы работы. У каталога таких проходов три, и все три уже разведены —
разведены механизмом, а не намерением:

| Сбор | Разбор |
|---|---|
| `consumers-sync` печатает расхождения ответов потребителей | задача #186: правится у них, а не здесь |
| `collect_proposals.py` тянет предложения из проектов | задача-«входящие снизу»: номер присуждает каталог |
| `check_bindings.py` печатает очередь «ничем» | заход окна: один тир за раз, по порядку номеров |

Разбор внутри сбора стоит трижды: контекст первой находки съедает окно до
последней, вторая половина прохода идёт хуже первой, а решение по первому
случаю принимается до того, как виден второй.

**На границе фазы спрашивают о МЕТОДЕ, а не о продукте**
([088](rules/ru/088-the-critic-checks-the-method-not-the-subject.md)). Вопрос
«критика метода» из карты выше — не «что не так с результатом», а: какая доля
результата действительно новая, чего фаза не покрыла, где заявленный метод
оказался мнимым. Границы фаз у каталога две:

- **построил гейт → приёмка.** Спрашивается: отвергает ли он ПРЕДМЕТ правила,
  а не свою границу; прогонялся ли объявленный третий исход; не подтверждает
  ли он сам себя ([146](rules/ru/146-a-green-gate-does-not-verify-its-premise.md));
- **закрыл тир очереди → замер.** Спрашивается: сколько закрыто РАБОТОЙ, а
  сколько переклассификацией; у скольких причина отказа осталась прежней и
  верна ли она до сих пор.

Вопрос задаёт не тот, кто делал фазу, — иначе он отвечает изнутри неё
([086](rules/ru/086-the-finder-does-not-grade-the-finding.md)). У окна это
означает отдельный заход после отчёта, а не абзац в конце того же.

## 🧩 Шов и обобщение

**Известная развилка получает шов сразу, общее заводится по третьему случаю**
([093](rules/ru/093-seam-early-generalisation-late.md)). Шов — минимальный
обратимый рефактор, фиксирующий контракт; обобщение — абстракция над
несколькими реализациями. Первое дёшево и обратимо, второе дорого и застывает.

**Швы, введённые рано** — все до того, как понадобился второй потребитель:

- `scripts/ghcli.py` — вызов площадки в одном месте: свой обработчик у каждого
  скрипта занял бы код возврата 2, а он принадлежит самому `gh`;
- ключ `--root` у гейтов — точка, в которую подставляется подделанное дерево;
  без него набор проверял бы состояние машины, а не решение гейта;
- `check_links.LINK_RE` берётся другими скриптами, а не переписывается: две
  формулировки «что считать ссылкой» разошлись бы молча
  ([022](rules/ru/022-one-canonical-document.md)).

**Обобщения, которых не завели, и это решение, а не забывчивость:**

- второй уровень группировки областей — случаев два, третьего нет;
- общий разбор таблиц для `check_roles.py` и `check_readers.py` — обе читают
  разметку, но спрашивают разное, и общий разбор связал бы их изменения;
- общий «сборщик снимков» для метрик выпуска и метрики «ничем» — считают они
  по разным деревьям и с разной целью.

**Признак, что правило нарушено:** абстракция, у которой ровно две
реализации, и вторая появилась вчера.

## 🚶 Из общей ветки обновляется только голова очереди

**Слилось изменение — подтягивать общую ветку надо в ТО, что пойдёт следующим,
а не во все открытые** ([052](rules/ru/052-only-the-head-of-the-queue-moves.md)).
Обновление всех после каждого слияния — квадрат холостой работы: каждая
подтяжка рождает событие, событие рождает прогон, прогон занимает очередь,
а к моменту, когда до ветки дойдёт черёд, общая ветка уедет снова.

**Замер по дереву 4 сентября: операций обновления ветки из общей у каталога
НОЛЬ** — ни в прогонах, ни в скриптах. Правило адресовано не механизму, а
**окну**: подтягивает общую ветку оно, руками, и потому держится это здесь, а
не гейтом. Гейт на нулевом предмете зеленел бы, не держа ничего
([146](rules/ru/146-a-green-gate-does-not-verify-its-premise.md)).

**Когда операция появится — она подпадает под правило сразу:** обновляется одна
ветка, та, у которой очередь ближе всего к слиянию, и следующая берётся после
того, как предыдущая слилась.

## 🔁 Перезапуск — это диагностика

**Упала одна работа — перезапускается она одна**, а не весь набор
([124](rules/ru/124-rerun-the-minimum-and-record-the-flake.md)). Площадка даёт
это кнопкой «re-run failed jobs»; перезапуск всего прогона прячет, что именно
было красным, и стоит очереди лишние минуты.

**Попытка ровно одна.** Второй перезапуск того же места — уже не диагностика, а
попытка получить нужный ответ повторением вопроса.

**Зелёное со второго раза — находка, а не починка.** Перезапуск разрешён в трёх
случаях, и каждый называется вслух при записи:

| Случай | Что записывается |
|---|---|
| причина найдена и устранена (правка тела, метка, слияние общей ветки) | ничего: это обычная починка, и её видно в изменении |
| работа умерла до первого теста — выкачка, установка, потеря исполнителя | фрагмент журнала: что упало и на каком шаге |
| та же работа зеленела на этом же коммите раньше | фрагмент журнала как **нестабильность**, с номером прогона |

Отдельного файла для нестабильностей здесь нет намеренно: запись едет тем же
фрагментом в [`changelog.d/`](changelog.d/), что и всякая другая починка, и там
же отвечает на вопрос «тянет ли это на правило»
([022](rules/ru/022-one-canonical-document.md)). Второй реестр разошёлся бы с
первым.

**«Флаки» причиной не является.** Работа, зеленеющая через раз, — это либо
общая площадка, которую набор не забрал себе
([149](rules/ru/149-the-suite-owns-its-temp.md)), либо порядок, на который он
опирается молча. Пока причина не названа, перезапуск — отсрочка, а не ответ.

## ✅ Перед толчком

```
python scripts/preflight.py
```

Прогоняет **шаги самого конвейера**, а не их пересказ: список берётся из
`ci.yml`, поэтому новый гейт попадает в прогон сам и помнить о нём никому не
нужно ([022](rules/ru/022-one-canonical-document.md)). Исходов три, как у
каждого гейта: `0` чисто · `1` находки · `2` проверка не отработала.

**Запускать его надо интерпретатором НЕ НИЖЕ объявленной планки.** Контейнер
окна может нести `python` старее, чем `requires-python` в `pyproject.toml`, и
тогда «чисто локально» снято не на той поверхности
([037](rules/ru/037-finding-status-depends-on-window.md)): доступное конвейеру
здесь упадёт, и починят это ВНИЗ — молча привязав дерево к версии, которой
проект не объявлял. Замер 4 сентября: планка `>=3.12`, все семь прогонов
`3.12`, окно `3.11.15`, и ни один механизм этого не спрашивал. Теперь
спрашивает `scripts/check_python_version.py`; ниже планки — заведите окружение
нужной версии и запускайте прогон из него.

**Чего прогон не проверяет, он называет сам.** Часть шагов живёт только на
изменении — им нужны его тело, метки и границы диапазона; локально предмета у
них нет, и молчание о них было бы неотличимо от проверенного
([075](rules/ru/075-a-guard-that-finds-nothing-must-fail.md)).

**Чек-листа здесь больше нет, и это исполнение
[002](rules/ru/002-rule-without-mechanism.md)**, а не сокращение
свода: его строки перечисляли то, что и так печатает гейт, а строка «метки
проставлены» требовала от читателя работы, которую делает `agent-pr.yml` по
тронутым путям. Заготовку с этим прогоном каталог раздаёт
потребителям с самого начала (`templates/preflight.py`), а у себя держал
список — ровно то расхождение, которое обязан ловить хранитель заготовок.
