Тег каталога в строке `uses:` у потребителя закреплял разметку действия, а не его код. Оба действия, которые каталог отдаёт наружу, выкачивали каталог ещё раз — по входу с умолчанием `main` — и исполняли скрипт оттуда: «входящие» по входу `ref`, гейт атрибуции по входу `catalogue-ref`. Заготовка подключения ставила тег только в `uses:`, а `CONNECT.md` обещал «тег закреплён». Теперь оба действия исполняют код из `GITHUB_ACTION_PATH`, куда площадка уже кладёт каталог на поставленном теге; входы атрибуции `catalogue` и `catalogue-ref` объявлены устаревшими, и заданное значение называется в прогоне. Выгрузка правил по умолчанию осталась свежей — это работа входящих. `scripts/check_workflows.py` держит, что составное действие исполняет свой код из своего пути; на прежних файлах он давал 2 находки. Правило 095 перестало держаться ничем.

> правилом не становится, потому что это 095 буквально — умолчание решало в пользу продукта (свежий код), а не пользователя (закреплённый тег), — и держать его стало можно сегодня, когда ответ «неприменимо» опроверг замер.
