Значок Python стал единым значком состояния «Python 3.14 3.15 │ linux windows mac │ coverage │ release / PyPI │ version» (решение владельца 1 октября): зоны разделены просветом, версия последней. Покрытие и версия берутся из файлов значков, которые проект уже собирает, а не меряются второй раз; «release / PyPI» показывает старшие два числа выпуска и зеленеет, когда номер на PyPI совпадает с последним выпуском, краснеет при расхождении и сереет, если проект на PyPI не публикуется. Цвета — палитра GitHub (`#2da44e` / `#cf222e` / `#8c959f`), те же, что у его ✓ и ✗ проверок; контраст белого текста по замеру: зелёный 2,1:1 → 3,2:1, красный 3,6:1 → 5,4:1, серый 2,7:1 → 3,0:1 — порога 4,5:1 зелёный и серый не достигают, как и значки shields, и выбран вид, а не порог. Отдельные значки «Релиз», «Версия» и «Покрытие» с витрины сняты как дубли; в наборе вопросов витрины ответы на них, а также на «зелены ли проверки», теперь ведут в единый значок. Проекту, у которого часть кода исполняется только на своей ОС, зона покрытия показывает второе число — покрытие по всем ОС: `coverage / all (os) 72% / 85%`, а без него — просто `coverage 72%`. Действие `python-badge` получило входы `coverage-json`, `coverage-all-json`, `version-json` и `pypi`; без них соответствующие зоны серые, так что подключение по `v1.5.0` продолжает работать.

Соседи: сужения признака нет — гейт сужения прочёл как символьный класс список аргументов `pb.svg([("3.14", "pass"), …], "pass")` в удалённой строке теста; регулярных выражений изменение не сужало, а функция `svg` снята целиком вместе со своим вызовом.
