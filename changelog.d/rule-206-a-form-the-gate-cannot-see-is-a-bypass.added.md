**Правило 206: форма, которую гейт не видит, становится обходом** (080, 180, 146,
`rules/ru/206-…`, `rules/en/206-…`).

Приехало из проекта механизмов как правило о ЦИТАТАХ и принято ШИРЕ, чем
предложено: тот же рисунок нашёлся у нас на разборе КОМАНДЫ. Требование: гейт,
ищущий предмет по форме записи, читает все формы, которыми предмет пишут в его
дереве, и набор форм берётся замером, а не памятью. Невидимая форма становится
обходом, и обходящий не знает, что обходит.

ТЕРРИТОРИЮ ОТДАЛА СОСЕДНЯЯ ЗАПИСЬ, а не мы решили. 180 разрешает предмет по ИМЕНИ
через импорты и своей же границей говорит, что к форме вызова не обращается вовсе.
075 про гейт, не нашедший предмета ВООБЩЕ; здесь он предмет находит, просто не
весь, и потому зеленеет законно.

СВОЙ ИНЦИДЕНТ, ЖИВОЙ И ДОРОГОЙ. Сторож `push_guard.py`, держащий правило 202, за
одну смену не сработал ни разу из трёх: ветки воскрешены толчком после слияния,
#529 и #531 закрыты дублями. Проверка воскрешения исправна — её просто не
вызывают. Замер по формам:

```
ВИДИТ | git push · cd X && git push · git push; echo
 слеп | for … do git push; done · while · if · ( … )
```

Кусок обязан начинаться с `git`, а внутри конструкции оболочки он начинается с
`do`. **И самое дорогое: цикл с повтором — форма ПРЕДПИСАННАЯ** инструкцией этого
же проекта. Сторож слеп именно к той форме, которой велено пользоваться, и пропуск
здесь не редкий случай, а норма.

ВТОРОЙ ЗАМЕР — ДО ПОСТРОЙКИ, А НЕ ПОСЛЕ ПОЛОМКИ: упоминаний правил ссылкой **775**,
голым числом **2052** — невидимой формы в 2,6 раза больше. Гейта цитат у нас нет
вовсе (204 держится документом), и потому это предупреждение: написанный под
ссылки, он видел бы 27% предмета и зеленел на остальном.

Замер соседа для сравнения: 1007 против 1744, и 23 правила названы ТОЛЬКО голым
числом; расширение формы нашло пять живых цитат неприменимых правил, из них один
настоящий дефект. Проверено откатом.

МЕХАНИЗМА НЕТ, И ЭТО ОЧЕРЕДЬ, А НЕ ОТКАЗ. Починка сторожа заведена задачей #533
решением владельца: сперва задача, потом правка. Гейт «у перечня форм есть замер
рядом» здесь не заводится намеренно — он проверял бы прозу возле кода, а такого
предмета машине не дать. Ответ разобран надвое (182): машина берёт случай с той же
командой внутри конструкции оболочки, человек — полноту перечня форм.
