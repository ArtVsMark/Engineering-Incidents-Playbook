Сторож толчка перестал читать **тело документа на входе** как команду.

Окно писало файл прогона через `cat > … <<'YML'`, и внутри файла стоял пример
для человека: «переименуйте ветку — `git push …`». Сторож разобрал строку
примера как настоящую команду и **отверг запись файла**. Отказ хука блокирует
саму команду, а не только сверку ветки, так что окно просто не смогло записать
файл.

Случай «строка в файле — не команда» в наборе сторожа уже был, но проверял он
запись **чужим инструментом**; запись через оболочку тем же случаем не
покрывалась — набор из одних правильных подделок проверяет сторожа наполовину
(140).

Теперь тело документа от `<<EOF` до закрывающей строки пропускается: это
данные, которыми пишут файл. Тот же приём, что у сторожа с перенаправлением —
то, что после признака перестаёт быть командой, дальше не разбирается. Заодно
разделителем команд стал и перевод строки: при записи файла через оболочку он
единственный разделитель, и без него настоящий толчок следом за документом
сторож не видел вовсе.

Три случая на оба края: тело документа не команда, толчок **после** документа
виден, незакрытый документ разбор не подвешивает.

> документа ею не является. Правилом не становится: предмет уже назван 137, и
