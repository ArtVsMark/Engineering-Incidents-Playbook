Списки путей из git читаются по NUL: семь мест брали их без `-z`, и четыре из них потом ЧИТАЛИ эти файлы — не-ASCII имя пришло бы экранированным и выпало из обработки молча. Гейт `check_subprocess.py` теперь держит оба требования к одному предмету: кодировку у текстовых вызовов и разделитель у списков путей. Равносильным ответом признан `-c core.quotePath=false` — так отвечали два места в дереве, и их докстроки это объясняют.

> правилом не становится: это исполнение 165, принятого предложением соседа в этой же смене. Своя граница дописана в гейт: у `git log --name-only -z` NUL'ами разделяются имена, а строка формата отдаётся как есть — без `%x00` разбор молча перестал находить даты
