Сторож толчка перестал считать восстановление файла переходом на ветку.
`checkout` решает две задачи разом, и различает их `--`: всё за ним — ПУТИ.
Разбор возвращал оттуда первое слово как имя ветки, и составная команда
`git checkout -- export/rules.json && git push -u origin своя` объявлялась
толчком в чужую — то есть отказ приходил на верную работу и в собственной
ветке окна. Замер 8 сентября: три формы из трёх ложны —
`checkout -- файл`, `checkout main -- файл` (дерево перед `--` тоже не
переход) и `checkout .`.

`--` отменяет ПЕРЕХОД, а не охрану: `git checkout -- файл && git push origin
чужая` остаётся находкой, и это закреплено случаем. Свернув признак в «в
команде есть `--` — не смотрим», сторож пропустил бы ровно то, ради чего
заведён (140).

Форма БЕЗ `--` намеренно оставлена как была. `git checkout export/rules.json`
и `git checkout agent/тема` неразличимы текстом — решает это сам git, глядя в
дерево, — и угадывать здесь значит запрещать недостоверное (051). Исключены
только `.` и `..`: их git не принимает как имя ссылки вовсе, а путём они
приходят постоянно.
