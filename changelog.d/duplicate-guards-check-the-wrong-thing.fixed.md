Сторожа дубликатов перестали заводить копии. Задачу-адресат искали через поисковый индекс площадки, а он догоняет с задержкой в минуты: два прогона с разницей в три минуты завели по своей задаче при обещанной одной. Теперь берётся обычный список, отбор идёт на месте — во всех местах, где так делалось, включая дежурного по общей ветке в `scripts/main_red.py`. Отдельно `agent-pr` открывал пустое изменение на ветке, уже слитой squash: коммиты после такого слияния не становятся предками общей ветки, и сторож смотрел на историю вместо содержимого.
Третий сторож той же породы: гейт связи с задачей читал тело изменения из `github.event`, то есть из снимка, сделанного в момент события. Правка тела снимок не трогает, а пере-прогон проигрывает его заново — гейт отказывал на уже исправленном. Теперь тело спрашивается живым.
